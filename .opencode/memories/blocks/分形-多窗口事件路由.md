# 分形-多窗口事件路由（sessionDirs 缓存）

- 事实：serve `/global/event` 全局事件流**不过滤实例目录**——多窗口（多工作区）下每个窗口的订阅都会收到所有工作区的事件；ipc.ts 的 `startEngineEvents` 需要按目录把事件路由到对应窗口
- 原则：分形每个窗口独立 SSE 订阅（2026-08-13 修复，原只在主窗口启动时建立订阅——第二窗口收不到 engine:event 无消息输出）；路由靠 `sessionDirs` 缓存（sessionID→directory），事件带 sessionID 时查缓存决定投递
- 反例：❌ 之前只在主窗口启动时建立订阅——多窗口场景第二窗口无消息输出；❌ serve 全局事件流不区分目录，单靠 URL query 的 directory 无法对事件流过滤
- ✅ 实现：index.ts `startEngineEvents(win, serverManager, () => winWorkspaces.get(win.id) ?? '')` 每次事件实时判断窗口工作区；ipc.ts sessionDirs 全量填充（session.list）+ 增量维护（session.created 的 info.directory）
- 结论：事件流按**全局广播**、HTTP 请求按 **directory query 路由**（见「serve 多实例路由」记忆）——两者机制不同，多窗口功能都要照顾到
