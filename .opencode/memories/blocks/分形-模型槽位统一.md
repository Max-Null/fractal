# 分形模型槽位统一（HIGH/LOW/VISION）

**事实**：三个模型槽位：
- HIGH = 主智能体（双星）→ 设置页模型下拉（cfg.model → applyModelAliases HIGH）
- LOW = 轻量任务（标题/润色/未来摘要）→ settings.json smallModel（空=跟随主模型；resolveSmallModel 读文件，损坏落 SMALL_MODEL 常量）
- VISION = 多模态（制图师 kimi-k3）→ VISION_MODEL 常量；provider-configs.json 支持多 provider（moonshotai-cn 只存 apiKey，key 空也写 models 定义——provider 可识别）

**原则**：agent 的 model 字段由 applyModelAliases 按 **agent 名槽位规则**替换（双星→HIGH / 工匠·参谋·助理→LOW / 制图师→VISION / 无 model 行跳过）——与源形态无关（预置/部署产物通吃）；空值兜底 SMALL_MODEL（agent 文件 model 行不能为空）。

**反例**：
❌ 传 `ds/deepseek-v4-pro`（serve 内置 provider id 是 deepseek——Model not found）
❌ GUI 写 opencode.json agent 段（.md 覆盖 JSON——无效，真相源是 agents/*.md frontmatter）

**结论**：GUI 改模型 = 改 .md frontmatter（或等分形 applyModelAliases 启动替换）；oc-plus 始终能夺回控制权（改源码 + deploy 覆盖）。
