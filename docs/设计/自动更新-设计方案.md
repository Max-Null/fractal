# 自动更新-设计方案

> 版本：v1.0 · 状态：待实现 · 2026-08-14 · 作者：双星团队
> 决策来源：docs/决策/2026-08-14-自动更新-转public+electron-updater.md

## 一、背景与目标

分形面向非编程人员，当前无任何更新机制——用户永远不知道有新版本，只能手动找安装包重装。

**目标**：借用 GitHub 实现「自动检查更新 + 一键更新」：应用启动静默检查，发现新版提示用户，用户一键下载安装重启，全程无需手动下载。

**用户已拍板**（2026-08-14）：
- 仓库 Max-Null/fractal 转 public（electron-updater 零 token 直读 Releases）
- 采用 electron-updater（差分更新、静默安装、自动重启，官方生态最成熟）
- 顺带升级 electron-builder 24.9.1 → 26.x（对 Electron 43 打包兼容）

## 二、现状盘点

| 项 | 现状 |
|----|------|
| 打包配置 | electron-builder.yml：NSIS 向导模式（oneClick:false、allowToChangeInstallationDirectory:true）、extraResources（bin sidecar + preset）、electronDownload mirror npmmirror |
| publish | `provider: generic, url: https://example.com/auto-updates`（占位符，需改为 GitHub） |
| electron-updater | **未安装**（dependencies 仅 @electron-toolkit/preload、@electron-toolkit/utils、@opencode-ai/sdk、ajv、jsonc-parser） |
| 版本 | package.json 1.1.0；Electron ^43.3.0（支持期到 2027-01）；electron-builder ^24.9.1（2023 年旧版） |
| 仓库 | Max-Null/fractal **private**（已拍板转 public）；无 CI（无 .github） |
| 更新 UI 挂载点 | SettingsPanel.vue「关于」tab：版本/引擎版本/预置版本/更新日志 |
| 主进程 | electron/main/：index.ts 注册 IPC、window.ts 窗口管理、ipc.ts 各领域 handler |

## 三、方案设计

### 总体架构

```
主进程 electron/main/updater.ts（新）
  · 封装 electron-updater（CJS require，项目主进程是 CJS 输出）
  · autoDownload=false：先提示再下载，不自动抢下载
  · 事件 → webContents.send('updater:status', ...) 推送渲染层
  · IPC handler：updater:check / updater:download / updater:quit-and-install
  · app.isPackaged 才启用（dev 模式完全禁用）

渲染层
  · electron-bridge.ts：updater 相关 IPC 封装 + onUpdaterStatus 订阅
  · SettingsPanel「关于」tab：「检查更新」按钮 + 状态区
  · 有新版 → ModalShell 确认弹窗（版本 + 变更摘要）→ 下载进度 → 重启安装
```

### D1：electron-updater 引入

- 安装 `electron-updater@^6.6.0`（与 electron-builder 26.x 配套）
- 主进程 CJS：`const { autoUpdater } = require('electron-updater')`（electron-updater 是 CJS 模块，主进程构建输出 CJS，直接 require 无 ESM workaround 需要）
- **注意**：electron-updater 与 electron-builder 必须同大版本配套（electron-updater 6.x ↔ electron-builder 24/26 均兼容，但用 26 配套的 6.6.x 最稳）

### D2：主进程 updater.ts

文件：`electron/main/updater.ts`（新建）

职责：
1. 初始化：`autoUpdater.autoDownload = false`；`autoUpdater.logger = 简化中文日志（复用现有 log 通道）`；dev 模式（`!app.isPackaged`）直接 return 不注册任何逻辑
2. 事件订阅（全部转发到渲染层，payload 精简）：
   - `checking-for-update` → `{ type: 'checking' }`
   - `update-available` → `{ type: 'available', version, releaseNotes }`（releaseNotes 取 info.releaseNotes，兼容 string | Note[]）
   - `update-not-available` → `{ type: 'not-available', version }`
   - `error` → `{ type: 'error', message }`（中文可读化：网络失败/无发布/未知）
   - `download-progress` → `{ type: 'progress', percent, transferred, total, bytesPerSecond }`
   - `update-downloaded` → `{ type: 'downloaded', version }`
3. IPC handler（注册在 ipc.ts 或 updater.ts 内 self-register，遵循项目现有 handler 风格）：
   - `updater:check` → `autoUpdater.checkForUpdates()`（返回 promise 结果，同时事件推送）
   - `updater:download` → `autoUpdater.downloadUpdate()`
   - `updater:quit-and-install` → `autoUpdater.quitAndInstall()`
4. 错误文案映射：`Error: Cannot find latest.yml` 类 → 「未找到更新信息」；网络类 → 「网络连接失败」；其余保留原始 message

### D3：IPC 事件契约

推送（主 → 渲染，webContents.send('updater:status', payload)）：

| payload.type | 含义 | 关键字段 |
|--------------|------|----------|
| checking | 检查中 | - |
| available | 发现新版 | version, releaseNotes |
| not-available | 已是最新 | version（当前版本） |
| progress | 下载中 | percent, transferred, total |
| downloaded | 下载完成 | version |
| error | 失败 | message |

请求（渲染 → 主，invoke）：`updater:check` / `updater:download` / `updater:quit-and-install`，全部 `Promise<void>`。

### D4：渲染层

**electron-bridge.ts**（扩展）：
- `checkForUpdates(): Promise<void>` → invoke('updater:check')
- `downloadUpdate(): Promise<void>` → invoke('updater:download')
- `quitAndInstall(): Promise<void>` → invoke('updater:quit-and-install')
- `onUpdaterStatus(cb: (status: UpdaterStatus) => void): () => void` → 订阅 'updater:status'，返回取消订阅函数（遵循现有 onSessionEvent 模式）

**SettingsPanel「关于」tab**：
- 布局：现有版本信息下方加「更新」区块：
  - 状态行：`当前版本 v1.1.0` + 检查更新按钮（lucide RefreshCw 图标）
  - 状态展示区（语义类 .about-updater-*）：
    - checking：按钮 loading「检查中…」
    - not-available：「已是最新版本」
    - available：高亮条「发现新版本 vX.Y.Z」+ 变更摘要（展开/收起）+「立即更新」按钮
    - progress：进度条 + 百分比 + 已下载/总量（MB）
    - downloaded：「更新已下载，重启后生效」+「重启并安装」按钮
    - error：错误提示（danger 色）+ 可重试
- 状态管理：SettingsPanel 内局部 ref（updaterState），订阅 onUpdaterStatus；**不引入全局 store**（弹窗只在此触发，D3 单写入点）
- 确认弹窗：发现新版时 ModalShell 弹窗（版本 + releaseNotes 摘要 + 取消/立即更新），点立即更新后弹窗关闭、状态区显示进度

**i18n**：settings 命名空间新增 `settings.update.*`（zh/en 双份）：
- updateCheck「检查更新」/ updateChecking「检查中…」/ updateLatest「已是最新版本」/ updateFound「发现新版本」/ updateDownload「立即更新」/ updateProgress「正在下载」/ updateRestart「重启并安装」/ updateError「检查失败」/ updateNoNotes「本次更新无变更说明」

### D5：检查时机

- **启动静默检查**：app ready 后延迟 10s 自动 checkForUpdates()（不打扰，有新版才弹）
- **手动检查**：关于页「检查更新」按钮随时可点
- 静默检查与手动检查共用同一状态通道，手动点击时状态区实时反馈

### D6：构建 publish 配置

electron-builder.yml 改动：
```yaml
publish:
  provider: github
  owner: Max-Null
  repo: fractal
```
- 打包自动生成 latest.yml + 安装包；`electron-builder --publish always` 时自动上传 GitHub Releases（需环境变量 GH_TOKEN）
- **保留** electronDownload mirror npmmirror（下载 Electron 二进制走镜像，上传 Release 不受影响）
- files 排除列表已有 dev-app-update.yml（打包不泄漏本地更新配置）

### D7：升级 electron-builder

- `electron-builder` 24.9.1 → `^26.15.3`（配套 electron-updater ^6.6.x）
- 升级风险控制：electron-builder 26 配置向后兼容（NSIS/extraResources/publish 结构不变）；升级后必须跑一次真实打包验证 NSIS 产物 + latest.yml 生成
- 顺带检查 electron-builder 26 是否默认 `electronUpdaterCompatibility` 变化（26 默认 latest.yml 现代格式，electron-updater 6.x 兼容，无需显式配置）

### D8：发布流程

无 CI，发布走手动脚本（后续可加 GitHub Actions）：
1. 手动 bump version（package.json + 变更记录）
2. `npm run build:win`（electron-builder 26.x，生成 dist 产物）
3. 带 GH_TOKEN 执行 `electron-builder --publish always`（上传 latest.yml + 安装包到 GitHub Releases，tag 自动生成 vX.Y.Z）
4. 人工复核 Release notes

### D9：错误处理

| 场景 | 表现 |
|------|------|
| 非打包环境（dev） | updater 完全禁用，关于页不显示更新区块或显示「开发模式不可用」 |
| 网络失败 / 无 Release | updater:error → 「检查失败：网络连接失败」可重试 |
| GitHub 无该版本发布 | update-not-available → 「已是最新版本」 |
| 下载中断 | error → 状态区错误提示，可重新点「立即更新」重试 |
| 未签名安装包 SmartScreen | 维持现状（安装时警告，不新增负担） |

### D10：边界与已知风险

- **NSIS assisted（oneClick:false）+ 自动更新**：electron-updater 支持，但用户改过安装路径时是已知 edge case——**验证阶段必须真实发布测试版验证**（D3 决策来源）
- extraResources（bin sidecar + preset 数百 MB）随安装包整体更新，逻辑不变
- 升级 electron-builder 可能引入打包配置兼容问题——升级后立即跑真实打包验证，不升级直接实施
