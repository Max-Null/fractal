# 历史子任务查看 — 设计方案

> 版本：v1.0 ｜ 日期：2026-08-09 ｜ 状态：待用户确认
> 关联：docs/原型/历史子任务查看-原型文档.md（镜像）
> 前置：子智能体可视化（实时 SubTaskCard 已上线，本方案补历史场景）

## 一、需求背景

实时子任务卡片只覆盖「运行期间/本 app 会话内」——重启后历史会话里子智能体活动不可见（task 结果文本在，但无卡片/无中间过程/无完整工作查看）。用户要求：**历史会话能看到子智能体块**。

## 二、现状与数据实证（2026-08-09 探针）

| 数据 | 结论 |
|------|------|
| serve DB part 表 | task 工具调用无 tool part 持久化（查 6 条全为 webfetch/read/edit 误匹配） |
| serve DB event 表 | task 调用完整事件存在（tool:task + messageID + input，output 含 `<task id="ses_...">`）——event 表无 API 暴露 |
| **v1 API `GET /session/{id}/message`** | **✅ 实测（140 条消息）：返回的 parts 里包含 task tool part（12 个），`state.output` 含 `<task id="ses_0a89..." state="completed">`**——serve API 动态注入 task part（part 表没有但 API 有）——**消息级精确关联可行** |
| serve 会话列表 | 子会话有 `parent_id` + `time.created` + `agent`（补充信息：agent 徽标/标题/时间） |

## 三、关键设计决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | 数据源 = **会话列表全量派生 + 消息 part 解析**（零新请求） | session store 已全量拉取；历史消息已在加载（toMessageData 已还原 tool part） |
| D2 | 归属 = **task part 解析精确关联**（正则提取 `<task id="ses_...">`） | v1 API 实测返回 task part；无需时间窗口近似 |
| D3 | 入口 = **assistant 消息块下方「🧩 N 个子任务」** | 消息级入口（用户拍板）；只显示**已完成**子会话（运行中的由实时 SubTaskCard 管理，避免双入口） |
| D4 | 列表项点击 → **复用 SubTaskDetail**（从 serve 拉全量） | 现有组件直接复用（subId 参数不变） |
| D5 | 列表项 = agent 徽标 + 标题（去 `(@xx subagent)` 后缀）+ 时间 + 时长 | 可读性；徽标映射复用 SubTaskCard 的映射 |
| D6 | 边界容错 | 无 task part 消息跳过；同消息多个 task 调用全部列出；解析失败降级（不显示入口，不阻塞渲染） |

## 四、归属算法（D2 细节）

```
输入：active 会话消息 messages（含 toolUses/contentBlocks）、该会话子会话列表 children（parent_id 匹配）
步骤：
1. 遍历 messages 的 tool 块（assistant.tool_use 或 user.tool_results）：
   - tool 名 === 'task' → 从 output/content 正则提取子会话 id：/<task id="(ses_[^"]+)"[^>]*>/
   - 提取到的 id → 关联到该消息（一条消息可挂多个子会话）
2. 子会话详情（agent/标题/时间）从 children 按 id 匹配补充
3. 输出 Map<messageId, SubTaskInfo[]>
```

## 五、组件改动

| 文件 | 改动 |
|------|------|
| `session.ts` | 新增派生：`childSessionsOf(parentId)`（全量列表 filter，已含）——或无改动（ChatPanel 直接 filter） |
| `chat.ts` | 新增 `associateSubTasks(messages)` 纯函数（归属算法，导出供测试） |
| `ChatPanel.vue` | 消息渲染时计算归属 Map；在对应 assistant 消息块下方渲染「🧩 N 个子任务」入口；展开态管理（单开） |
| `SubTaskHistoryList.vue`（新） | 行内展开列表：agent 徽标 + 标题 + 时间 + 时长；点击项 → 打开 SubTaskDetail（ModalShell 挂载在 ChatPanel） |
| `SubTaskDetail.vue` | 复用（无改动） |
| locales | 子任务/展开/收起文案 |

## 六、测试要点

- `extractSubTaskIds` 纯函数：单 id / 多 id（同消息多次 task）/ 无 id / 非 task 工具不误匹配 / 状态非 completed 也提取（只要 output 有 `<task id>`）
- 归属 Map 构建：多消息多 task 正确挂载
- ChatPanel：入口显示条件（有已完成子会话才显示）/ 展开收起 / 点击项开详情弹窗
- 回归：实时 SubTaskCard 不受影响（两个机制独立）

## 七、风险与边界

- **task part 依赖 serve API 动态注入**：若 serve 版本升级后不再注入（v2 400 未实测成功——v2 API 的 400 可能是参数问题，后续可复测）——降级方案：时间窗口近似（D2 备选，算法已可独立实现）
- 子会话在实时卡片与历史入口**双显示**（运行中：实时卡片；历史入口只显示已完成——互斥设计）
- 子会话列表里找不到的 task id（会话被删/跨工作区）——入口隐藏该项
