# 模型配置-设计方案（Agent 模型 GUI 化接管）

> 版本：v1.0 ｜ 状态：待确认 ｜ 读者：技术团队
> 关联：docs/设计/设置页设计方案.md（设置页 LLM 区现状）

## 一、背景与目标

oc-plus 项目当前用「占位符 + 部署时替换」管理 agent 模型（`model-aliases.json` → deploy.mjs 替换 `DS_MODEL_LOW/HIGH/VISION` 占位符）。本方案由 fractal GUI 接管：**设置页直接写各 agent 的 model 字段**，消除 oc-plus 的构建期替换机制，用户改模型不再需要改文件 + 重新部署。

## 二、OC 机制查证（2026-08-08，源码确认）

### 2.1 small_model ≠ 子 agent 默认模型（关键误区）

`opencode.json` 的 `small_model` 字段（config.ts 定义）：
> *"Small model to use for tasks like title generation in the format of provider/model"*

唯一调用点在 `prompt.ts` 的 `ensureTitle`（生成会话标题），以及 `project-copy.ts`（项目复制摘要）。**只覆盖 utility 任务，与子 agent 干活用的模型无关。**

### 2.2 子 agent 无 model 行的真实行为（task.ts）

```typescript
const model = next.model ?? {
  modelID: msg.info.modelID,   // ← 继承调用者（主 agent）的模型
  providerID: msg.info.providerID,
}
```

官方文档同样确认：*"subagents will use the model of the primary agent that invoked the subagent"*。

**推论**：想让子 agent 用低配模型，必须**显式写 model 字段**；删掉 model 行 = 继承主模型（往往是贵的那个）。

## 三、Agent 模型分配方案

| Agent | model 字段 | 值 | 说明 |
|-------|-----------|-----|------|
| 双星（primary） | 全局 `model`（设置页选） | 用户切 flash/pro | 设置页已有模型选择能力，经 ensureConfig 联动，重启跟随 |
| 工匠（subagent） | 显式写 | `ds/deepseek-v4-flash` | 编码执行，确定性任务，单价 1/10 |
| 参谋（subagent） | 显式写 | `ds/deepseek-v4-pro` | 战术纠偏需推理 |
| 助理（subagent） | 显式写 | `ds/deepseek-v4-flash` | 极轻量 |
| 制图师（subagent） | 显式写 | `moonshotai-cn/kimi-k3` | 视觉多模态（models.dev 内置 provider） |
| 军师（subagent） | **无 model 行** | 继承双星 | 天然 HIGH（pro） |
| 导师（subagent） | **无 model 行** | 继承双星 | 天然 HIGH（pro） |
| `small_model` 字段 | 独立配置 | `ds/deepseek-v4-flash` | 标题生成等 utility 任务省钱 |

> 注意：军师/导师**故意不写** model 行（继承主模型），若以后主模型切 flash，它们自动跟随——符合「顾问用主模型」的语义。

## 四、GUI 设计

### 4.1 设置页新增「Agent 模型」区（LLM 设置区下方）

```
┌─ Agent 模型 ──────────────────────────┐
│ 主模型（双星）      [ds/deepseek-v4-pro ▼]  ← 与现有 LLM 设置联动
│ 工匠               [ds/deepseek-v4-flash ▼]
│ 参谋               [ds/deepseek-v4-pro ▼]
│ 助理               [ds/deepseek-v4-flash ▼]
│ 制图师             [moonshotai-cn/kimi-k3 ▼]
│ 军师               [继承主模型 🔒]          ← 只读提示，不显示下拉
│ 导师               [继承主模型 🔒]
│ 辅助任务模型        [ds/deepseek-v4-flash ▼]  ← small_model 字段
│ （说明：辅助任务 = 会话标题生成等轻量场景）
└─────────────────────────────────────────┘
```

- 模型下拉数据源：`provider.list` 返回值（现有 LLM 设置已用）
- 军师/导师显示「继承主模型」锁定态，避免误配

### 4.2 ⚠️ 写入目标：agent .md 文件（不是 opencode.json！）

**OC 配置加载顺序**（config.ts `loadInstanceState` 源码确认）：

```
全局 opencode.json → 项目 opencode.json → 【最后】agents/*.md
```

`result.agent = mergeDeep(result.agent, ConfigAgent.load(dir))`——remeda mergeDeep 语义 **source 覆盖 target**，即 **`.md` 文件的 model 字段覆盖 opencode.json 的 agent 段**。

**推论**：
- GUI 写 opencode.json 的 agent.model → 被 .md 覆盖 → **无效**，必须直接编辑 agent .md 文件的 frontmatter
- 编辑目标：`~/.config/opencode/agents/*.md`（deploy 产物，格式见 4.3）
- 主模型（双星）：写全局 opencode.json 的 `model` 字段（.md 无冲突，双星 .md 无 model 行时继承全局）
- `small_model`：写全局 opencode.json（无 .md 冲突）

### 4.3 agent .md 编辑格式（frontmatter）

```markdown
---
description: 编码工匠——接指令、理解代码、动手改、自测、报告、停止
mode: subagent
model: "ds/deepseek-v4-flash"    ← GUI 只改这一行
permission: ...
---
```

> GUI 保存 model 后，文件 mtime 更新。deploy.mjs copyDir 用 `src.mtime > dest.mtime` 判断覆盖——**GUI 改过的文件比源码新，下次部署不会被冲掉**；oc-plus 改源码 .md 后再部署可夺回控制权（医者不能自医原则：oc-plus 必须始终能覆盖 GUI）。

### 4.4 与 oc-plus 的衔接

- fractal 直接编辑部署产物 .md（与 oc-plus 共用同一真相源，无第二套配置）
- oc-plus 的 deploy.mjs `patchAgentModel` 保持现状（部署时按 model-aliases.json 替换占位符）——GUI 改的是替换后的真实模型名，互不冲突
- 过渡期：fractal 未配置的 agent 仍走占位符替换，配置后 .md 里已是真实模型名，deploy 因 mtime 保护不覆盖

## 五、风险与边界

| 风险 | 影响 | 缓解 |
|------|------|------|
| 用户误删工匠 model 行 | 工匠变 pro（继承主模型），成本回归 | GUI 显示锁定态提示「此 agent 必须显式选模型」 |
| agent 名不匹配 .md 文件名 | OC 不识别 | 下拉只列 `agent.list()` 返回的现有 agent |
| 主模型切换后军师跟随 | 军师变 flash 影响审查质量 | 设计语义如此（顾问随主模型），设置页说明文案 |
| small_model 配置为 kimi | 标题生成花钱（kimi 贵） | 默认值 flash，仅列出同 provider 低配模型 |
| GUI 改 .md 后 deploy 重新部署 | GUI 配置被冲掉 | copyDir mtime 保护（src.mtime > dest.mtime 才覆盖）——GUI 改过的文件比源码新，不被覆盖 |
| 编辑 .md 语法错误 | OC 加载 agent 失败 | GUI 写 frontmatter 前校验 YAML（复用现有 JSONC 校验模式），失败提示不落盘 |
