# 模型配置-设计方案（Agent 模型 GUI 化接管）

> 版本：v1.2 ｜ 状态：已实现（2026-08-09 分形侧落地） ｜ 读者：技术团队
> 关联：docs/设计/设置页设计方案.md（设置页 LLM 区现状）｜ docs/知识/oc-engine/模型配置-设计方案.md（归档版 + 实现对照）
> 镜像：docs/原型/模型配置-原型文档.md（产品/UI 视角）

## 一、背景与目标

oc-plus 项目当前用「占位符 + 部署时替换」管理 agent 模型（`model-aliases.json` → deploy.mjs 替换 `DS_MODEL_LOW/HIGH/VISION` 占位符）。本方案由 fractal GUI 接管：**设置页直接管理各 agent 的模型槽位**，用户改模型不再需要改文件 + 重新部署。

**分形侧已实现（2026-08-09）**：模型槽位统一（HIGH/LOW/VISION）+ 设置页「主模型」下拉 + 设置页「轻量模型」下拉 + 设置页 kimi（多模态）API Key 输入 + 预置 agents mtime 保护（真相源原则落地）。

## 二、OC 机制查证（2026-08-08，源码确认）

### 2.1 small_model ≠ 子 agent 默认模型（关键误区）

`opencode.json` 的 `small_model` 字段（config.ts 定义）：
> *"Small model to use for tasks like title generation in the format of provider/model"*

唯一调用点在 `prompt.ts` 的 `ensureTitle`（生成会话标题），以及 `project-copy.ts`（项目复制摘要）。**只覆盖 utility 任务，与子 agent 干活用的模型无关。**

### 2.2 子 agent 无 model 行的真实行为（task.ts）

```typescript
const model = next.model ?? {
  modelID: msg.info.modelID,   // ← 继承调用者（主 agent）的模型
  providerID: msg.info.providerID,
}
```

官方文档同样确认：*"subagents will use the model of the primary agent that invoked the subagent"*。

**推论**：想让子 agent 用低配模型，必须**显式写 model 字段**；删掉 model 行 = 继承主模型（往往是贵的那个）。

### 2.3 真相源原则（2026-08-09 查证，两项目共享）

- **OC 加载顺序：全局 opencode.json → 项目 opencode.json → 最后 .md（覆盖 JSON）**
- 推论：deploy 部署的 .md 必然生效（不依赖 GUI）；**GUI 写 opencode.json 的 agent 段无效**（被 .md 覆盖）
- **.md 文件是模型配置的真相源，GUI 只是它的可视化编辑器**
- mtime 保护：GUI 改过（mtime 更新）的 .md 不被预置升级冲掉；oc-plus 重新 deploy 可夺回
- oc-plus 架构原则「医者不能自医」：真相源在文件层，GUI 是可选增强层；违背此原则的设计必须显式标注理由

## 三、Agent 模型分配方案（槽位制）

| Agent | model 字段 | 槽位 | 值（默认） | 说明 |
|-------|-----------|------|-----------|------|
| 双星（primary） | 无 model 行 + 全局 `model` | HIGH | 设置页主模型（flash/pro） | 全局 model 字段由 ensureConfig 联动设置页选择 |
| 工匠（subagent） | 显式写 | LOW | `deepseek/deepseek-v4-flash` | 编码执行，确定性任务，单价 1/10 |
| 参谋（subagent） | 显式写 | LOW | `deepseek/deepseek-v4-flash` | ⚠️ 与 oc-plus 方案差异：oc-plus 建议 pro（战术纠偏需推理），分形槽位规则归 LOW——分形侧默认按 flash，可调整 |
| 助理（subagent） | 显式写 | LOW | `deepseek/deepseek-v4-flash` | 极轻量 |
| 制图师（subagent） | 显式写 | VISION | `moonshotai-cn/kimi-k3` | 视觉多模态（models.dev 内置 provider，key 由设置页 kimi 输入提供） |
| 侦查兵（subagent） | 显式写 | **不归槽位** | 保持源值 | ⚠️ 机制特殊：插件驱动 + DeepSeek Anthropic 兼容端点（`https://api.deepseek.com/anthropic`）实现联网搜索——模型槽位不适用，预置同步时随源更新 |
| 军师（subagent） | **无 model 行** | 继承 HIGH | 继承双星 | 天然 HIGH（pro），顾问用主模型 |
| 导师（subagent） | **无 model 行** | 继承 HIGH | 继承双星 | 天然 HIGH（pro） |
| `small_model` 字段 | 独立配置 | LOW | `deepseek/deepseek-v4-flash` | 标题生成等 utility 任务省钱（设置页「轻量模型」下拉） |

> 注意：军师/导师**故意不写** model 行（继承主模型），若以后主模型切 flash，它们自动跟随——符合「顾问用主模型」的语义。

## 四、GUI 设计（分形已实现）

### 4.1 设置页入口（三个控件，非「每 agent 一个下拉」）

```
┌─ LLM 设置 ────────────────────────────┐
│ 模型（主模型）        [v4-pro ▼]        ← HIGH：双星 + 全局 model
│ API Key（DeepSeek）   [•••••••• 👁]     ← 唯一必填
│ API Key（制图师/kimi）[•••••••• 👁]     ← 多模态，VISION 槽位
│ 轻量模型              [flash ▼]         ← LOW：工匠/参谋/助理 + small_model
│ （说明：轻量任务 = 会话标题生成/消息润色等）
└────────────────────────────────────────┘
```

- **主模型下拉**（现有 LLM 设置）：v4-flash / v4-pro——联动 ensureConfig 写全局 `model`（HIGH）
- **轻量模型下拉**（高级设置区，2026-08-09 新增）：跟随主模型（默认）/ v4-flash / v4-pro——写 settings.json `smallModel` → resolveSmallModel → ensureConfig 写 `small_model`（空值删除字段）+ applyModelAliases LOW 槽位
- **kimi API Key 输入**（2026-08-09 新增）：password/明文切换 + 保存重启 serve（新增 provider 必须重启才被识别）——写 provider-configs.json `moonshotai-cn.apiKey` → ensureConfig 写 provider

### 4.2 ⚠️ 写入目标：agent .md 文件（不是 opencode.json agent 段！）

**OC 配置加载顺序**（config.ts `loadInstanceState` 源码确认）：

```
全局 opencode.json → 项目 opencode.json → 【最后】agents/*.md
```

`result.agent = mergeDeep(result.agent, ConfigAgent.load(dir))`——remeda mergeDeep 语义 **source 覆盖 target**，即 **`.md` 文件的 model 字段覆盖 opencode.json 的 agent 段**。

**推论**：
- GUI 写 opencode.json 的 agent.model → 被 .md 覆盖 → **无效**——分形 oc-config.ts 已核对**不写 agent 段**（L157 注释：agent 由 agents/*.md 提供）
- 模型槽位写入 = 编辑部署产物 agents/*.md 的 frontmatter（applyModelAliases 按槽位规则替换 model 行）
- 主模型（双星）：写全局 opencode.json 的 `model` 字段（.md 无冲突，双星 .md 无 model 行时继承全局）
- `small_model`：写全局 opencode.json（无 .md 冲突）

### 4.3 agent .md 编辑格式（frontmatter）

```markdown
---
description: 编码工匠——接指令、理解代码、动手改、自测、报告、停止
mode: subagent
model: "deepseek/deepseek-v4-flash"    ← GUI（applyModelAliases）只改这一行
permission: ...
---
```

> GUI 保存 model 后，文件 mtime 更新。deploy.mjs copyDir 用 `src.mtime > dest.mtime` 判断覆盖——**GUI 改过的文件比源码新，下次部署不会被冲掉**；oc-plus 改源码 .md 后再部署可夺回控制权（医者不能自医原则：oc-plus 必须始终能覆盖 GUI）。

### 4.4 与 oc-plus 的衔接

- fractal 直接编辑部署产物 .md（与 oc-plus 共用同一真相源，无第二套配置）
- oc-plus 的 deploy.mjs `patchAgentModel` 保持现状（部署时按 model-aliases.json 替换占位符）——GUI 改的是替换后的真实模型名，互不冲突
- 过渡期：fractal 未配置的 agent 仍走占位符替换，配置后 .md 里已是真实模型名，deploy 因 mtime 保护不覆盖

### 4.5 分形实现对照（2026-08-09 落地）

| 能力 | 实现 | 位置 |
|------|------|------|
| HIGH 槽位（双星） | 全局 model = ensureConfig（设置页主模型下拉联动），缺省 pro | `electron/main/oc-config.ts` ensureConfig |
| LOW 槽位（工匠/参谋/助理） | applyModelAliases 按 `MODEL_SLOT_RULES` 替换；值 = resolveSmallModel（设置页轻量模型）`\|` SMALL_MODEL 常量 | `electron/main/preset.ts` + `electron/main/oc-config.ts` |
| VISION 槽位（制图师） | VISION_MODEL 常量（moonshotai-cn/kimi-k3）；kimi provider + key 由设置页输入 → ensureConfig 写入 | `electron/main/oc-config.ts` |
| 槽位规则 | `双星.md→high / 工匠·参谋·助理.md→low / 制图师.md→vision`；无 model 行跳过（继承主模型） | `electron/main/preset.ts` MODEL_SLOT_RULES |
| 幂等 | 内容一致不写盘（mtime 不变） | `electron/main/preset.ts` |
| 立即生效 | saveProviderConfig 无条件调用 applyModelAliases（HIGH 缺省读 cfg.model） | `electron/main/ipc.ts` |
| mtime 保护 | copyDir preserveUserEdits 模式（目标比源新跳过）+ copyFileKeepMtime（拷贝恢复源 mtime 保证比较语义） | `electron/main/preset.ts` |
| small_model | settings.json `smallModel`（空=跟随主模型不写字段）→ resolveSmallModel → ensureConfig | `electron/main/settings.ts` + `oc-config.ts` |
| 主模型切换 | 设置页下拉 → saveSettings 引擎快照 → ensureConfig → 重启或 applyModelAliases | `src/renderer/src/stores/settings.ts` + `ipc.ts` |

## 五、风险与边界

| 风险 | 影响 | 缓解 |
|------|------|------|
| 用户误删工匠 model 行 | 工匠变 pro（继承主模型），成本回归 | 槽位制 + 设置页轻量模型下拉固定值（不提供删除入口） |
| agent 名不匹配 .md 文件名 | OC 不识别 | 槽位规则固定 agent 名单（双星/工匠/参谋/助理/制图师），与预置一致 |
| 主模型切换后军师跟随 | 军师变 flash 影响审查质量 | 设计语义如此（顾问随主模型），设置页说明文案 |
| small_model 配置为 kimi | 标题生成花钱（kimi 贵） | 轻量模型下拉仅列同 provider 低配模型（flash/pro） |
| GUI 改 .md 后 deploy 重新部署 | GUI 配置被冲掉 | copyDir mtime 保护（src.mtime > dest.mtime 才覆盖）——GUI 改过的文件比源码新，不被覆盖 |
| 编辑 .md 语法错误 | OC 加载 agent 失败 | applyModelAliases 只改 model 行（frontmatter 其余原样）；无 YAML 校验（值与白名单一致） |
| 参谋归 LOW 与 oc-plus 方案冲突 | 参谋推理能力下降 | 已标注差异（三节表），如需 pro 将参谋.md 移入 HIGH 规则或显式改文件 |

## 六、测试要点

| 测试场景 | 前置条件 | 操作 | 预期结果 |
|----------|----------|------|----------|
| 三槽位替换 | 预置初始化后 | 跑 preset.test 槽位用例 | 双星→cfg.model、工匠/参谋/助理→LOW 值、制图师→VISION |
| 设置页改主模型 | 设置页 | 改模型保存 | cfg.model 更新 + applyModelAliases 双星跟随（无需重启） |
| 设置页改轻量模型 | 设置页高级区 | 选 pro 保存 | settings.json smallModel + opencode.json small_model + 工匠等 LOW 槽位变 pro |
| kimi key 保存 | 设置页 | 填 key 保存 | provider-configs moonshotai-cn + opencode.json provider 写入 + serve 重启 |
| mtime 保护 | 用户改过 agents/*.md | 预置升级（bump） | 用户改过的保留，其余更新 |
| 无 model 行 | 军师/导师 | 升级 | 不被写入（继承主模型） |
