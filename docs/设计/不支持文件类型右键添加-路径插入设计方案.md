# 不支持文件类型右键添加-路径插入设计方案

> 版本：v1.0
> 日期：2026-08-16
> 状态：已确认待实施
> 关联：右键菜单「添加到会话」链路（FileTree.vue → window attach-files 事件 → ChatPanel onAttachFiles）

## 一、问题背景

右键菜单「添加到会话」把 `isOfficeAttachment`（pdf/docx/xlsx/zip 等模型端不支持的类型）也添加为附件，发送时弹 ConfirmDialog 确认，**确认后仍以附件内容形式发送给 LLM**——实测 pdf 报 "this model does not support pdf input"，确认步骤纯属白费。

用户反馈：「这个设计太傻了，改成：不支持的文件类型直接右键添加时直接给消息输入框添加路径」。

## 二、需求确认（用户已选定）

- **交互方案 A**：不支持类型右键添加 → 附件条不出现，路径直接插入输入框
- **格式**：双引号包裹（防空格断词）`"C:\Users\MaxNull\Desktop\测试.docx"`
- **位置**：光标位置（无焦点时退化末尾追加）

## 三、现状链路

```
FileTree.vue 右键「添加到会话」
  → window.dispatchEvent(CustomEvent("attach-files", { name, path }))
  → ChatPanel.vue onAttachFiles（所有文件一律 push attachedFiles）
  → InputBar chips 显示附件
  → handleSend 检测 office 附件 → ConfirmDialog → doSend 以附件内容发送
```

## 四、关键设计决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | `insertAtCursor` 作为 InputBar 新增暴露方法，不改 `setText` | `setText` 是整体覆盖语义（FilePreview DOM 选择器用），覆盖会吞掉用户已输入内容；insertAtCursor 只动光标处，互不干扰 |
| D2 | 光标位置插入：读 `textarea.selectionStart/End` | 用户正在输入时路径插在光标处不破坏现有文字；无焦点（selectionStart 0）时退化末尾追加 |
| D3 | 双引号包裹 + 路径内 `"` 转义 | Windows 路径空格常见，引号防 LLM 断词；转义防极端路径注入 |
| D4 | `onAttachFiles` 内分流：office → insertAtCursor；文本 → 原附件逻辑 | 单点分流，不动发送链路，风险最小 |
| D5 | `quotePath` 为 ChatPanel 私有纯函数 | 唯一使用方，不提前抽象；测试通过组件行为断言 |

## 五、改动清单（3 文件）

### 1. `src/renderer/src/components/chat/InputBar.vue`
`defineExpose` 新增：
```ts
/** 光标位置插入文本（无焦点/光标在末尾 → 末尾追加）；插入后光标移到插入文本后并聚焦 */
insertAtCursor: (text: string) => {
  const el = document.querySelector(".chat-textarea") as HTMLTextAreaElement | null
  const pos = el ? el.selectionStart : input.value.length
  const next = input.value.slice(0, pos) + text + input.value.slice(pos)
  input.value = next
  autoResize()
  nextTick(() => {
    const el2 = document.querySelector(".chat-textarea") as HTMLTextAreaElement | null
    if (el2) { el2.focus(); const caret = pos + text.length; el2.setSelectionRange(caret, caret) }
  })
},
```

### 2. `src/renderer/src/components/chat/ChatPanel.vue`
- 新增私有函数：
```ts
/** 路径加双引号并转义内部引号（office 附件右键添加 → 输入框路径，防空格断词/注入） */
function quotePath(path: string): string {
  return `"${path.replace(/"/g, '\\"')}"`
}
```
- `onAttachFiles` 分流：
```ts
function onAttachFiles(e: Event) {
  const files = (e as CustomEvent).detail as { name: string; path: string }[]
  for (const f of files) {
    // office/二进制附件（模型端不支持读取）：不添加附件条，路径直接插输入框光标处（2026-08-16 用户要求）
    if (isOfficeAttachment(f.name)) {
      inputBar.value?.insertAtCursor(quotePath(f.path))
      continue
    }
    if (!attachedFiles.value.some(af => af.path === f.path)) {
      attachedFiles.value.push(f)
    }
  }
}
```

### 3. 测试
- **InputBar.test.ts**：`insertAtCursor` 光标中插入 / 末尾追加 / 光标后移（mock textarea selectionStart）
- **ChatPanel.test.ts**：office 文件 → 不 push 附件 + 调 insertAtCursor（mock inputBar 暴露）；文本文件 → 仍 push 附件

## 六、边界与风险

- 路径含双引号：转义 `\"`（极端，Windows 文件名不允许 `"`，防御性处理）
- 多文件右键：逐个插入，空格分隔（引号自带分隔语义）
- 支持类型（txt/md/json 等）现有附件行为不变
- 无风险：纯前端交互，不动 IPC/主进程/OC 引擎；`insertAtCursor` 新增暴露不影响既有 `setText` 调用方（grep 确认仅 FilePreview 用 setText）
- 插入不自动发送（用户可继续编辑再发）

## 七、验收标准

1. 右键添加 docx/pdf → 附件条无新增 chip，输入框光标处出现 `"路径"`，光标在引号后
2. 右键添加 txt/md → 附件条照常 chip（回归）
3. 用户在输入框已有文字时右键添加 → 路径插光标处，原文字不丢
4. 发送含路径消息 → 不弹 office ConfirmDialog
5. 相关测试全绿
