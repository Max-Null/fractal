## 撰写原则

1. **先事实后意图**：每个模块先写「当前代码长什么样」（文件/函数/数据流），再写「为什么这样」，最后列「缺口待决」
2. **用户拍板点显式标注**：G 编号缺口表，用户逐条选 A/B/C
3. **决策变更必须回填**：方案文档的阶段规划若实现时偏离，必须在本文档记录变更原因（如 db.ts SQLite 未实现 → 01 文档已记录）
