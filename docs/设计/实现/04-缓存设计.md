# 实现设计 04：缓存设计

> 版本：2026-08-07 ｜ 缓存三件套：会话缓存（LRU）/ 配置双写（防加载错位）/ 事件重连（防丢流）

## 一、会话消息缓存（渲染进程 sessionCache）

- **结构**：`Map<sessionId, { messages, todos }>`，LRU 上限 20 条
- **写入**：切换会话前 `saveSessionCache`（深拷贝，保留流式中间态 isStreaming）
- **读取**：切回时 `loadFromCache`（LRU 命中刷新）→ 命中即恢复完整状态（含流式中间态）；未命中 → serve `session.messages` 拉取
- **后台会话**：SSE 全局广播 → `handleBackgroundStreamEvent` 增量写入缓存（与活跃会话同逻辑）——切回不丢流（G5 拍板：优先缓存）
- **淘汰**：超 20 条删最旧（Map 插入序）

## 二、配置双写缓存（主进程）

- opencode.json + opencode.jsonc 双写同内容——serve 加载候选的「缓存一致性」
- 写触发：ensureConfig（受管字段）/ ensurePresetConfig（预置字段）/ saveProviderConfig（用户改 key）——三者都「读现有 → 写自身字段」merge，互不覆盖（交叉测试锚定）

## 三、事件流补偿

| 层 | 机制 |
|----|------|
| 订阅 | SDK `event.subscribe` 内置指数退避重连（3s ×2 递增 30s 封顶） |
| 断线补 | 会话切换/重启时 `session.messages` 全量拉取兜底（01 文档 G3） |
| 去重 | events.ts 纯函数去重三原则（02 文档第三节） |

## 四、引擎状态缓存

- `ready()` 的 startPromise 单例（并发共享）——stopServer 后置空（防死进程缓存）
- sidecarBroken 标记：内置 spawn 失败本会话跳过内置（防重复失败）

## 五、测试锚点

- chat.test：缓存保存/恢复/LRU 淘汰/后台增量
- events.test：去重三原则 + 重连逻辑（合成事件）
- server-manager.test：ready 单例/stopServer 缓存失效
