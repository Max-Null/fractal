# 实现设计 03：数据库与持久化

> 版本：2026-08-09（基线精确化） ｜ 决策：**无本地业务数据库**（serve 唯一数据源）——早期方案规划的 SQLite 未实现，决策变更已在 01 文档记录

## 一、数据存哪（全景）

| 数据 | 存储位置 | 说明 |
|------|---------|------|
| 会话/消息历史 | OC serve 数据目录（`<userData>/config/opencode/` 下的 serve 数据库） | serve 原生存储，GUI 只读写 API |
| API Key/Provider 配置 | `<userData>/provider-configs.json` | 明文 JSON（单文件 allow 权限保护） |
| serve 引擎配置 | `<userData>/config/opencode/opencode.json` + `.jsonc`（双写） | jsonc 优先加载（实测） |
| UI 偏好（主题/agent/权限模式等） | SQLite `<userData>/oc-gui.db`（settings 表）+ localStorage 镜像 | 双写防丢 |
| 预置包（agents/skills/plugins） | 打包只读 `resources/preset/` → 初始化拷贝到 `<userData>/config/opencode/` | .preset-version 版本标记 |
| 内存缓存 | 渲染进程 sessionCache（LRU 20） | app 关即失 |

## 二、为什么没有本地业务库

- serve 已提供完整会话/消息 API（list/get/messages/fork/rename/delete）——再存一份 = 双写一致性灾难
- 历史决策变更：早期方案「GUI 本地 SQLite 会话表」→ 实测后改为「serve 唯一源」（01 文档 G1-G5 拍板）

## 三、settings 存储细节

- `settings` 表（SQLite）：UI 偏好持久化；`initFromDb` 启动恢复
- localStorage 镜像：`sb-*` 键（快速读 + 降级）
- 保存链路：store 变更 → saveCurrentConfig（防抖）→ SQLite + localStorage

## 四、配置双写（opencode.json / .jsonc）

- **坑（已修）**：serve 候选加载 `opencode.jsonc` 优先——早期只写 .json 导致 serve 从未加载分形配置
- 现状：oc-config.ensureConfig + preset.ensurePresetConfig 都双写两文件（同内容）

## 五、测试

- ipc.test：JSON 读写往返（tmpdir）；oc-config.test：merge 语义；preset.test：幂等 + 交叉
- 无 SQLite 测试基建（settings 层轻依赖）——SQLite 由 better-sqlite3 驱动，测试走临时目录
