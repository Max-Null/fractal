## 一、背景与目标

设置页（SettingsPanel.vue，1042 行）自迁移以来经多轮迭代（DeepSeek 专属重写、权限 6→4、数据模式开关、kimi key、消息排布、昵称头像、轻量模型、日志级别、预置技能），从未做整体梳理。当前问题：

1. **布局混乱**：三栏 `flex-wrap` 平铺（每栏固定 300px），「引擎设置」里混了 API 配置与会话参数，「高级设置」折叠区塞了重要性差异大的项。
2. **技术债**：8 段几乎重复的自定义下拉（语言/主题/字号/模型/权限/思考深度/排布/日志级别/轻量模型）；大量 emoji 当图标（📋🔒✏️⚡🐢🧠🚀），违反项目「图标一律用 lucide-vue-next」规范。
3. **功能缺失**（用户明确提出的 6 项）：思考过程节点开关、图片头像、默认主 Agent、子 agent 模型独立配置、系统通知、高级设置样式整理。

**目标**：布局重构（左侧导航 + 右侧单列）+ 补 6 项功能 + 清理技术债（抽通用组件 + 换 lucide）。

### 2.2 已有设计约定（必须遵守）

- **真相源原则**（模型配置 v1.2）：OC 配置加载顺序 = 全局 opencode.json → 项目 opencode.json → **最后 agents/*.md**。子 agent 模型真相源是 `agents/*.md` frontmatter 的 `model` 行，GUI 是它的可视化编辑器；**写 opencode.json 的 agent 段无效**（被 .md 覆盖）。
- **槽位制**（模型配置 v1.2 + 契约）：`applyModelAliases` 按 `agents-manifest.json` 契约的槽位替换 .md 的 model 行。
- **配置分层**（settings.ts）：第 1 层 DEFAULT_SETTINGS 默认值 / 第 2 层 settings.json / 第 3 层密钥（provider-configs.json）。`parseAndValidate` 只保留 DEFAULT_SETTINGS 已知 key——**新字段必须加入 DEFAULT_SETTINGS + settings.schema.json，否则被丢弃**。
- **ui.* 三写**：UI 偏好同时写 localStorage + SQLite + settings.json。

## 三、关键设计决策

| 编号 | 决策 | 理由 |
|------|------|------|
| **D1 布局** | 左侧导航（6 tab）+ 右侧单列表单 | 功能 25+ 个，平铺必然爆炸；侧边栏可扩展、分类彻底（用户已拍板） |
| **D2 组件抽取** | 抽 4 个通用组件：SettingsSelect / SettingsInput / SettingsToggle / SettingsSection | 消灭 8 段重复下拉 + 统一视觉 |
| **D3 图标** | emoji 全部换 lucide-vue-next | 项目图标规范（开发规范四） |
| **D4 思考节点开关** | 新增 `ui.showThinking`（默认 true）；`v-show` 控制时间线 thinking 节点显隐，thinking 数据不删 | 用户确认：现有节点已是可展开一条，开关仅控制显隐，切回即恢复 |
| **D5 头像** | emoji 沿用 `ui.avatar`；新增 `ui.avatarImage` 存图片文件名；图片存 `<userData>/avatar/` | 图片+emoji 都要（用户拍板） |
| **D6 头像 IPC** | 新增 `avatar:pick`（选图复制）/ `avatar:clear`（删图） | 图片文件由主进程管理，渲染进程不直接持文件路径 |
| **D7 头像渲染** | 有图片显示 `<img>`，否则 emoji；清除图片回退 emoji | 字段分离，互不干扰 |
| **D8 默认主 Agent** | currentAgent 下拉（7 agent），补设置页入口 | 字段已存在默认「双星」，仅缺 UI |
| **D9 子 agent 覆盖表** | 新增 `agentModelOverrides`（settings.json，`Record<agent名, 模型全名>`，默认 `{}`） | 用户意图存 settings.json（主进程 applyModelAliases 需读） |
| **D10 覆盖优先级** | applyModelAliases：有合法覆盖 → 用覆盖值；无覆盖 → 槽位默认 | 「不设置显示默认」的落地 |
| **D11 候选按能力限定** | 文本 agent（双星/工匠/参谋/军师/助理）选 flash/pro；侦查兵选 ds-anthropic 端点；制图师选 kimi-k3 | 防呆：配错模型导致图像/联网能力静默失效（用户拍板） |
| **D12 「跟随默认」语义** | 从 overrides 删该 agent 条目 → 回到槽位默认 | 覆盖是增量，删除即还原 |
| **D13 通知 IPC** | 新增 `notification:show`（title/body） | Electron Notification 由主进程发 |
| **D14 通知配置** | `ui.notifications`（enabled + replyDone/engineError/permissionPending/subtaskDone），进 settings.json（ui.* 三写） | 所有配置统一进 settings.json，不搞 localStorage 特例（用户拍板） |
| **D15 通知默认** | 全局默认关；开启后 4 场景默认「回答完成」开、其余关 | 桌面通知 opt-in（用户拍板） |
| **D16 引擎异常通知** | 由主进程（server-manager exit 回调）直接 Notification，不走前端 | 引擎异常时前端可能已断连 |
| **D17 高级设置** | 折叠区 → 独立「高级」tab，字段不变 | 样式整理，非字段变更 |

## 五、新功能设计

### 5.1 思考过程节点开关（D4）

- **字段**：`ui.showThinking: boolean`（默认 `true`）
- **存储**：ui.* 三写（localStorage + SQLite + settings.json，跟随 messageLayout 模式）
- **生效**：时间线组件（node-timeline）的 thinking 节点加 `v-show="settings.showThinking"`；开关是纯前端显隐，thinking 数据（contentBlocks）不动，切回立即恢复
- **入口**：AI 行为 tab

### 5.2 图片头像（D5/D6/D7）

- **字段**：`ui.avatar`（emoji，现有）+ `ui.avatarImage`（图片文件名，新增）
- **存储**：图片文件 `<userData>/avatar/avatar.{ext}`；`ui.avatarImage` 存文件名（三写）
- **IPC**：
  - `avatar:pick`：openDialog 选图 → 校验扩展名（png/jpg/jpeg/webp）→ 复制到 avatar 目录（统一命名 `avatar.{ext}`，覆盖旧图）→ 返回文件名
  - `avatar:clear`：删除 avatar 目录文件 → 清 `ui.avatarImage`
- **渲染**：消息区/顶栏头像组件，`ui.avatarImage` 非空且文件存在 → `<img :src>`；否则显示 emoji（空 emoji 兜底「我」字，沿用现状）
- **头像图片 URL**：主进程暴露只读路径（`avatar:getPath` 或 file:// 协议），渲染层不直接拼接绝对路径

### 5.3 默认主 Agent（D8）

- **字段**：`currentAgent`（现有，localStorage，默认「双星」）
- **入口**：AI 行为 tab，SettingsSelect，选项 = 7 个预置 agent（双星/工匠/参谋/军师/助理/侦查兵/制图师）
- **生效**：currentAgent 已由 chat:sendMessage 的 `agent` 参数消费，改设置即改新会话默认；不重启

### 5.4 子 agent 模型独立配置（D9-D12，后端改动最大）

#### 5.4.1 覆盖表存储

- settings.json 新增字段 `agentModelOverrides: Record<string, string>`（默认 `{}`）
- 示例：`{ "工匠": "deepseek/deepseek-v4-pro", "参谋": "deepseek/deepseek-v4-flash" }`
- key = agent 名（去 .md），value = 模型全名（provider/model 格式）

#### 5.4.2 候选范围（按能力限定）

| Agent | 槽位 | 「跟随默认」值 | 可选候选 |
|-------|------|---------------|---------|
| 双星 | high | 主模型 | deepseek-v4-flash / pro |
| 工匠 | low | 轻量模型 | flash / pro |
| 助理 | low | 轻量模型 | flash / pro |
| 参谋 | inherit | 继承主模型 | flash / pro |
| 军师 | inherit | 继承主模型 | flash / pro |
| 侦查兵 | anthropic | ds-anthropic/deepseek-v4-flash | ds-anthropic flash / pro |
| 制图师 | vision | moonshotai-cn/kimi-k3 | kimi-k3（唯一） |

> 注：参谋/军师现状为 inherit（无 model 行，继承主模型）。用户显式覆盖 → 写 model 行（从继承变固定）；「跟随默认」→ 不写（保持继承）。

#### 5.4.3 applyModelAliases 改造（preset.ts）

现状逻辑（`electron/main/preset.ts:424`）：按槽位 `slotValues` 替换 .md 的 model 行，inherit 跳过。

改造后：

```
1. 读 settings.json 的 agentModelOverrides（fsp.readFile + JSON.parse，损坏兜底 {}）
2. for 每个 rule（契约 agents）:
   override = overrides[agent名] 且值在候选白名单内
   if override:
      value = override           // 用户显式覆盖（含 inherit 槽位也写 model 行）
   elif rule.slot === 'inherit':
      continue                   // 无覆盖的 inherit 保持继承
   else:
      value = slotValues[rule.slot]  // 槽位默认
   替换 model 行（值不变不写盘，保持幂等 + mtime 保护）
```

- **白名单校验**：候选范围表（5.4.2）硬编码于 preset.ts，非法覆盖值忽略（回退槽位默认）
- **inherit 覆盖**：被覆盖的 inherit agent 需写 model 行——`/^model:.*$/m` replace 在无 model 行文件上不匹配，需额外处理（无 model 行时在 frontmatter 追加一行）；实施时确认 frontmatter 结构再定

#### 5.4.4 联动触发

- `agentModelOverrides` 加入 settings.ts 的 `ENGINE_KEYS`（变更触发 `syncEngineConfig`）
- `syncEngineConfig` 在 ensureConfig 之后追加 `applyModelAliases(userDataDir)`（重新按覆盖表替换 .md）
- 前端选完模型 → 写 settings.json → 主进程联动 → 替换 .md → 下次会话生效（不重启 serve，与模型变更同语义）

#### 5.4.5 前端 UI

- AI 行为 tab「子 agent 模型」分组：7 行 SettingsSelect
- 每行：label = agent 名 + 槽位说明，选项 = 「跟随默认（当前值）」+ 候选模型
- 选「跟随默认」→ 从 overrides 删 key；选具体模型 → 写 key

### 5.5 系统通知（D13-D16，全新）

#### 5.5.1 配置与存储

- `ui.notifications`：`{ enabled: boolean, replyDone: boolean, engineError: boolean, permissionPending: boolean, subtaskDone: boolean }`
- 存储：进 settings.json（ui.* 三写：localStorage + SQLite + settings.json，跟随 messageLayout 模式）
- 默认：`enabled=false`；首次开启 enabled 时，`replyDone=true` 其余 `false`

#### 5.5.2 IPC

- `notification:show(title, body)`：主进程 `new Notification({title, body})`；仅 Windows 通知中心可用时弹出，异常吞掉（通知失败不阻断主流程）

#### 5.5.3 触发点

| 场景 | 触发位置 | 通道 |
|------|---------|------|
| AI 回答完成 | 前端：assistant 消息 isStreaming 由 true→false（消息流结束回调） | 前端检查开关 → notification:show |
| 引擎异常 | 主进程：server-manager exit 回调（非主动停止且非零退出） | 主进程直接 Notification（不经前端） |
| 权限请求待处理 | 前端：收到 permission 请求事件时 | 前端检查开关 → notification:show |
| 子任务完成 | 前端：subtask 事件流结束（task 子 agent 完成） | 前端检查开关 → notification:show |

## 十、风险与边界

- **inherit 覆盖写行**：无 model 行的 .md 需在 frontmatter 追加 `model` 行——需确认 frontmatter 结构（`---` 包裹），实施时小心不破坏 description/mode/permission 其他行
- **覆盖表与槽位默认漂移**：主模型/轻量模型切换时，「跟随默认」的 agent 值跟着变（符合语义）；显式覆盖的 agent 值固定不变
- **mtime 保护**：applyModelAliases 幂等（值不变不写盘）保证 mtime 不被无谓更新，用户改过的 .md 不被预置升级冲掉（沿用现状）
- **通知权限**：Windows 首次通知需系统授权，失败静默（不阻断）；引擎异常通知依赖主进程存活（serve 崩溃 ≠ 主进程崩溃，主进程仍在可发通知）
- **头像图片安全**：只接受图片扩展名 + 复制到受控目录；不直接引用用户原始路径（防删除/移动后失效）
