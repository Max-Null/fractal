# 诊断信息弹窗重构-设计方案

> 版本：v1.2 ｜ 状态：已实现（2026-08-14 提交 108f22d + bfbf8bb；v1.2 2026-08-15 增量——引擎日志 level 高亮 + 三标签页搜索）｜ 读者：技术团队
> 关联：src/renderer/src/components/chat/ChatPanel.vue（诊断面板现状所在地）

## 一、背景与目标

诊断面板（ChatPanel.vue 1340-1410 行，方案 D7 调试面板 → 用户反馈通道「诊断信息」）自迁移以来从未整体梳理，用户反馈「样式和功能很混乱」。现状问题：

1. **样式错位**：借用 `attach-bar`（附件浮层，bottom 160px 底部弹出）当弹窗容器、`system-msg-bar`（系统消息条）当标题栏——这两个是消息流组件样式，语义完全错位；大量内联 style 覆盖（background/border/box-shadow 全内联）；Unicode 符号当图标（✕ 🔄 ▸ ▾），违反项目「图标一律用 lucide-vue-next」规范；无居中、无动画、无统一弹窗外壳。
2. **结构膨胀**：3 个标签页（事件日志/引擎日志/控制台日志）的逻辑 + 渲染全部内联在 1727 行的 ChatPanel.vue 里，无独立组件。
3. **功能混乱**：两个复制按钮语义重叠（复制诊断信息 vs 复制当前标签页）；标题「诊断信息 (N)」的 N=当前会话事件数，切到引擎日志页时数字与内容无关；打开按钮与标题各显示一套数字。

**目标**：抽独立组件 `DiagnosticsModal.vue` + 复用项目统一弹窗外壳 ModalShell + 样式语义化（去内联、换 lucide）+ 理顺标题/复制按钮语义 + 增强错误行高亮（用户确认）。

### 2.2 事件日志行格式（错误高亮依据）

debugLog 行已有稳定前缀（useStreamProcessor 写入）：
- `❌ ${t(key)}`——错误（476 行）
- `⚠️`——权限/工具输入警告（341-342 行）
- 其他：`📨 unknown type`、`🔌 engine status`、`🔐 control_request` 等普通行

**serve.log / renderer.log 行无统一错误标记**（服务端日志格式不定），不做关键词猜测高亮（避免误标）。

> **v1.2 修订**：实测 serve.log（OpenCode serve stderr tee 落盘）为**结构化日志**——每行含 `level=INFO/WARN/ERROR` 字段（如 `timestamp=... level=ERROR run=abc message=boom`）。「格式不定」限制已被事实推翻：serve 日志可按 `level=` 精确分类。renderer.log（渲染层 console 桥落盘，格式 `[时间] [标签] 内容`）仍无 level 字段，保持不高亮。

## 三、关键设计决策

| 编号 | 决策 | 理由 |
|------|------|------|
| **D1 独立组件** | 新建 `src/renderer/src/components/chat/DiagnosticsModal.vue`，3 标签页逻辑 + 渲染全部迁入 | 解决 ChatPanel.vue 1727 行膨胀；组件自包含，可独立测试 |
| **D2 统一外壳** | 复用 `ModalShell.vue`（size="xl"，居中 modal）替代手搓浮层 | ModalShell 已有 Teleport/遮罩点击关闭/ESC/× 三通道，消除 attach-bar 借用；符合项目弹窗模式（AskUserQuestion/ContextUsageModal 同款） |
| **D3 Props 契约** | `open: boolean` + `emit('close')`，由 ChatPanel 的 `debugLog.visible.value` 驱动 | 与其他 modal（ContextUsageModal `:open` `@close`）一致 |
| **D4 状态归属** | `debugTab`/serve/renderer 日志状态迁入 DiagnosticsModal 内部 ref；`debugLog`（useDebugLog）保持全局单例 | 日志拉取是面板自包含行为；debugLog 是跨组件写入（useStreamProcessor）+ 读取（按钮行数），保持全局 |
| **D5 语义化样式** | 面板内部 scoped SCSS `.diag-*` 类，全部去掉内联 style 覆盖，颜色走 CSS 变量 | 项目 SCSS 规范（嵌套反映 DOM、CSS 变量优先） |
| **D6 lucide 图标** | 面板内按钮图标用 lucide-vue-next（X/Copy/RefreshCw/ChevronUp 等）替代 ✕ 🔄 ▸ ▾ | 项目图标规范（开发规范四）；ModalShell 自身的 × 保持现状（全局组件，改动波及 AskUserQuestion/ContextUsageModal 等，超范围） |
| **D7 错误行高亮** | 事件日志行按前缀分类：`❌` → error（var(--danger)）、`⚠️` → warn（var(--warning)）、其余 muted。**（v1.2 修订）** 引擎日志行解析 `level=` 字段：`level=ERROR` → error、`level=WARN` → warn、其余 normal（`classifyServeLine` 正则 `/level=([A-Z]+)/`）；serve.log 结构化字段是高亮的稳定依据，不再受「格式不定」限制；renderer.log 无 level 字段仍不高亮 | 用户确认的增强项；仅对有稳定标记的事件日志 + 结构化 serve.log 做，避免误标 |
| **D8 标题语义** | 标题固定「诊断信息」；行数显示移到内容区顶部（当前标签页实际行数） | 消除「标题数字与内容无关」的混乱 |
| **D9 复制按钮语义** | header 只留「复制诊断信息」（v1.1 升级为**全量包**：应用名+版本+事件日志+serve.log+renderer.log，serve/renderer 读取 allSettled 降级不阻断）；「复制当前标签页」移到标签页栏（图标+文字）做单页拷贝 | 原 v1.0「复制日志」仅图标放 header，与「复制诊断信息」并排造成「两个复制按钮」困惑；引擎页两按钮内容重叠（都含 serve.log）——v1.1 用户拍板：全量包 vs 单页拷贝，边界清晰 |
| **D10 定时轮询** | 弹窗打开且当前标签页为 serve/renderer 时每 3s 自动重读日志（`watch([props.open, debugTab])` 控制 setInterval 启停，切到 events 页/关弹窗即停，onUnmounted 清理）；`loadServeLog/loadRendererLog` 加 loading guard 防轮询堆积 | 推翻 v1.0「面板不自动轮询（原型 4.3）」——serve.log 是引擎实时输出，手动刷新对排查不友好，用户拍板改 3s 轮询 |
| **D11 日志搜索（v1.2）** | 标签页栏右侧统一搜索框（`searchQuery` ref + `matchSearch` 大小写不敏感过滤）；三个标签页各自 filtered computed（事件/引擎/控制台）；行数显示过滤后命中数（`命中/总数`，无关键词仅总数）；空态区分「无匹配」与「无日志」 | 用户反馈：日志多时无法快速定位 ERROR。搜索仅过滤显示，**不影响复制内容**（copyDebugLog 仍复制原始行——排查上下文完整）；搜索框 lucide Search 图标 + X 清除按钮，样式对齐 diag-tab 体系 |

## 四、组件设计

### 4.1 DiagnosticsModal.vue 接口

```ts
props: { open: boolean }
emit:  ['close']
// 内部状态
debugTab: ref<'events' | 'serve' | 'renderer'>
serveLogLines / serveLogLoading / serveLogError / serveLogPre
rendererLogLines / rendererLogLoading / rendererLogError / rendererLogPre
// 内部函数
switchDebugTab(tab)   // 切标签页；进 serve/renderer 页即拉取
loadServeLog()        // readServeLog(500)，超长滚底（nextTick + scrollTop=scrollHeight）
loadRendererLog()     // readRendererLog(500)，同上
copyDebugLog()        // 复制当前标签页内容
copyDiagnostics()     // getAppInfo + readServeLog(500) 打包
copyText(text)        // textarea 兼容法
// 计算
eventLines: computed<{text, level}[]>  // debugLog.lines 按前缀映射 level
```

### 4.3 模板结构

```html
<ModalShell :open="open" size="xl" @close="emit('close')">
  <template #header>
    诊断信息  <!-- D8：固定标题，不显示数字 -->
    <span class="flex-1" />
    <button @click="copyDebugLog">复制日志</button>  <!-- lucide Copy -->
    <button @click="copyDiagnostics">复制诊断信息</button>  <!-- lucide Package/ClipboardCopy -->
  </template>
  <div class="diag-tabs">  <!-- 3 个标签页按钮 + 当前行数（D8：行数在内容区顶部，与标签页同行） -->
    <button ...>事件日志</button>
    <button ...>引擎日志</button>
    <button ...>控制台日志</button>
    <span class="flex-1" />
    <span class="diag-count">当前行数 N</span>  <!-- 当前标签页实际行数 -->
  </div>
  <div class="diag-log">  <!-- 内容区，max-h + 滚动 -->
    <template v-if="debugTab==='events'">
      <div v-for="line in eventLines" :class="['diag-log-line', `diag-log-line--${line.level}`]">{{ line.text }}</div>
    </template>
    ...
  </div>
  <template #footer>
    <div class="diag-footer">日志用于排查，可复制发给开发者</div>  <!-- D9 隐私提示 -->
  </template>

```

> 注：ModalShell 的 header slot 放按钮需要 flex 布局——ModalShell 已提供 header 行，按钮直接放 header 内。

## 五、错误行高亮实现

- `eventLines` computed：遍历 `debugLog.lines.value`，按前缀映射 level：

| 前缀 | level | class |
|------|-------|-------|
| `❌` 开头 | `error` | `diag-log-line--error`（color: var(--coral)） |
| `⚠️` 开头 | `warn` | `diag-log-line--warn`（color: var(--warning)） |
| 其他 | `normal` | 默认（color: var(--text-muted)） |

- 引擎日志（v1.2）：`classifyServeLine` 正则 `/level=([A-Z]+)/` 提取 level 字段 → 同一套 class：

| level 字段 | level | class |
|------|-------|-------|
| `level=ERROR` | `error` | `diag-log-line--error` |
| `level=WARN` | `warn` | `diag-log-line--warn` |
| `level=INFO` / 无字段 | `normal` | 默认 |

- 行渲染从 `<pre>` 整体文本改为逐行 `<div>`——pre 的整块文本无法按行着色，逐行渲染是必要改造；行内容仍用 `white-space: pre-wrap` + `word-break: break-all` 保持换行语义
- 性能：debugLog 上限 200 行，computed 映射成本可忽略；serve 日志 500 行上限同理

## 六、数据流

```
useStreamProcessor → debugLog.add(line)  [全局单例，跨会话隔离]
        ↓
ChatPanel 打开按钮: debugLog.lines.length → (N)
ChatPanel: debugLog.visible.value → :open  → DiagnosticsModal
DiagnosticsModal: debugLog.lines → eventLines → 渲染
ChatPanel @close → debugLog.visible.value = false
```
