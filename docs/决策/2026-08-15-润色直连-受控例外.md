# 决策：AI 润色走 DeepSeek 直连 —「OC 唯一引擎」的受控例外

> 日期：2026-08-15
> 状态：已决策
> 决策人：MaxNull（用户提出「退回最初方案，由分形自己调用 DS 接口来处理」）
> 关联文档：[输入框优化-设计方案.md](../设计/输入框优化-设计方案.md) v1.1（D6 废弃 → D6'）
> 结论绑定：OpenCode 1.18.x（serve 并发缺陷 #21524 / #32010 / #35472 截至 2026-08 仍 open）

---

## 一、背景

AI 润色（polish）原实现走「serve 临时会话」：主进程创建临时会话 → `promptAsync` → 轮询 messages 60s → 提取回复 → 删临时会话。用户报告：**会话进行时润色无法使用**（转圈后报错）。

根因：当前会话 busy 时，serve 对临时会话的 `prompt_async` 被 accept（返回 204）但**回合不调度**，分形轮询 60s 拿不到 assistant 文本 → 报「润色超时」。

## 二、关键事实（联网查证 + 本地代码确认）

### 2.1 serve 并发缺陷是上游未修复问题

| Issue | 现象 | 状态（2026-08） |
|---|---|---|
| #21524 | `prompt_async` 对 idle session 返回 204 但回合不启动，间歇性 | closed not_planned |
| #32010 | 异步 prompt 被静默丢弃（accepted but never scheduled），调用方看到 204 成功 | open |
| #35472 | `GET /session/status` 在 prompt 流关闭后仍报 busy（stale busy） | open |

同目录多会话另有 SQLite 共享风险（#31307 / #28249 / #21215）。OC serve 架构支持多会话并发，但**当前版本的实际调度不可靠**，且修复时间不可控。

### 2.2 分形侧叠加问题

- 润色临时会话创建时**未绑定 cwd**（主会话都传了 `session.create({ cwd })`），无目录会话在 serve 的目录化调度中身份特殊。
- 分形轮询策略（500ms × 120 = 60s）假设「promptAsync 接受后必然有结果」——对 serve 并发缺陷不成立。

### 2.3 直连方案技术可行性（本地确认）

- 主进程已能读 `provider-configs.json` 的 DeepSeek apiKey/baseUrl（`settings:loadProviderConfigs`、`deepseek:getBalance` 既有模式）。
- 早期设置页设计本就有「推理 URL（polish 用）」字段（设置页设计方案 v1.0），直连润色并非新引入概念。
- 润色是纯文本任务（原实现强制 `agent: build` 不执行工具），**不依赖 serve 的工具执行 / 文件访问 / 会话管理能力**，直连零能力损失。

## 三、决策

1. **AI 润色改为主进程直连 DeepSeek `chat/completions`**：读 provider-configs.json 的 apiKey/baseUrl → `buildPolishPrompt` 组装 → fetch → 提取 `choices[0].message.content` → AbortController 60s 超时。
2. **「OC 唯一引擎」约束的范围界定**：OC 唯一引擎指**对话 / agent 任务**（工具执行、会话管理、上下文）全部由 OC 完成；润色作为**轻量文本改写任务**（无工具、无会话、无历史依赖），走 DeepSeek 官方 API 直连属于**受控例外**——不创建任何 serve 会话、不触碰会话历史、不与 serve 调度交互。
3. **模型跟随设置**：`resolveSmallModel`（设置页「轻量模型」，默认 deepseek-v4-flash；显式选「跟随主模型」则用 DEFAULT_MODEL deepseek-v4-pro）。
4. **回退条件**：serve 并发缺陷修复（#21524/#32010/#35472 关闭）后，评估是否回归「引擎临时会话」方案；若回归，撤销本决策。

## 四、风险与边界

| 风险 | 等级 | 应对 |
|---|---|---|
| 直连绕过 serve 隔离，API Key 在主进程持有 | 低 | key 仍只在主进程读取（provider-configs.json），渲染层经 IPC 调用不接触 key |
| 直连请求不经过 OC 配置（permission/agent 规则） | 已消除 | 润色无工具调用，无权限诉求；模型跟随设置页轻量模型 |
| 会话进行时仍可润色（与原「临时会话」同源冲突） | 已消除 | 直连与会话调度完全解耦 |
| 网络/超时错误 | 低 | AbortController 60s + 中文错误提示（401/未配 key/网络失败分类） |
| 与「基座选择（维持 OC）」决策冲突 | 无 | 直连仅润色一条轻量通道，不改基座、不引入新引擎 |
