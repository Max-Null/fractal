# 分形开发规范

> 版本：v1.0
> 来源：整合自 cc-gui 开发规范（`CLAUDE.md`、`docs/设计/设计决策参考.md`、`docs/知识/CSS语义化命名规范.md`），仅收录引擎无关条目；CC 专属内容已剔除，引擎交互按 OC 语义重写。
> 适用：分形（oc-gui）前后端开发与 cc-gui 设计资产迁移。迁移代码必须符合本规范，迁移本身也是对规范的继承验证。

## 一、编码总则

### 1.1 禁止手搓轮子

**写任何新代码前按序检查：**
1. Grep 搜索已有实现
2. 检查 `src/composables/` 有无对应 `useXxx()`
3. 检查 `src/lib/utils.ts` / `tauri-bridge.ts`
4. 检查同类 `.vue` 组件是否已有相同逻辑

常见违规：组件间复制粘贴逻辑、手写 `invoke()` 不走 bridge、新写已有 util 函数。

### 1.2 组件与数据流

- Props ↓ / Events ↑，**禁止 `defineModel`**
- 所有 Tauri 调用走 `tauri-bridge.ts`，不在组件中直接 `invoke()`
- 全局状态用 Pinia stores

### 1.3 i18n 硬性要求

所有面向用户的字符串必须中英双语，新增文案同时添加到 `zh.json` 和 `en.json`。

### 1.4 Rust 硬性要求

- 禁止 `panic`/`unwrap`/`expect`（`run()` 入口和 `#[cfg(test)]` 除外）
- 返回 `Result<T, String>`
- 禁止 `unsafe`

### 1.5 动手前必做

1. Grep 已有实现，检查 composables/lib/同类组件
2. **修改 `src-tauri/` 下任何 .rs 文件前** → 对照本文件「四、设计决策参考」逐条检查
3. 写 UI 前 → Grep 同类组件，复制其模板和 class 模式。颜色用 CSS 变量，禁止硬编码色值

### 1.6 阶段性完成必做

1. 补充测试（检查 `.test.ts`）
2. 更新设计文档（如有设计变更）
3. Git commit（见「五、Git 提交规范」）

## 二、CSS 语义化命名规范

> 来源：cc-gui `docs/知识/CSS语义化命名规范.md`，全文继承。

**DOM 元素必须有语义 class 名。** 裸 Tailwind 长链和 inline style 在代码审查时不可读，沟通时无法定位，重构时无法搜索。

```html
<!-- ❌ 禁止：你说"那个 w-1.5 shrink-0 cursor-col-resize 的 div"我听不懂 -->
<div class="w-1.5 shrink-0 cursor-col-resize hover:bg-[var(--accent)]/30 transition-colors select-none"
     style="background: var(--accent-dim)" />

<!-- ✅ 正确：你说"拖拽把手"我立刻定位 -->
<div class="panel-drag-handle" />
```

### 2.1 三 token 阈值

任何 `class="..."` 含 **3 个或以上** Tailwind/utility token → 提取为语义 class。

```
❌ class="flex items-center gap-2 px-3 py-2"
✅ class="toolbar-group"
```

### 2.2 inline style 同等待遇

`style="..."` 含 **3 条或以上** CSS 规则 → 收进 class。

```
❌ style="background: var(--bg-surface); border-bottom: 1px solid var(--border-dim); color: var(--text-muted)"
✅ class="sticky-question-bar"
```

### 2.3 BEM 风格命名

```
组件前缀-区块--状态
```

| 命名 | 含义 |
|------|------|
| `sb-header` | Shell → Header |
| `panel-drag-handle--active` | Panel → 拖拽把手 → 激活态 |
| `msg-row--user` | 消息行 → 用户消息变体 |
| `file-panel-tab--open` | 文件面板 → 抽屉标签 → 展开态 |

命名来源：**HTML 注释里描述的元素名。** 如果在注释里叫"拖拽把手"，class 就叫 `xxx-drag-handle`。

### 2.4 颜色只用 CSS 变量

禁止硬编码色值（`#06d6a0`、`rgba(255,255,255,0.03)` 等），统一用 `var(--xxx)`。

### 2.5 通用样式提取

出现 3 次以上的相同 class 组合 → 提取为全局通用 class。

```
❌ 四处重复：
  class="px-3 py-1.5 rounded-md text-xs font-medium transition-colors hover:bg-[var(--bg-hover)]"

✅ 提取到 main.css：
  .btn-ghost { ... }
  四处改为：class="btn-ghost"
```

### 2.6 审查命令

```bash
# 找出所有 class 链超过 40 字符的文件（≈ 4+ Tailwind token）
grep -rn 'class="[^"]{40,}"' src/ --include="*.vue"

# 找出 inline style 过多的文件
grep -c 'style="' src/**/*.vue | sort -t: -k2 -rn | head -20
```

### 2.7 例外

以下可以保留 Tailwind/inline：

- **动态条件样式**：`:style="{ color: visible ? 'var(--accent)' : 'var(--text-muted)' }"` —— 条件分支无法用纯 CSS 表达
- **单属性布局微调**：`class="ml-2"`、`class="shrink-0"` —— 2 个以下 token 可以保留
- **第三方组件覆盖**：修改第三方组件样式时优先用 `:deep()` + CSS，其次用单 token 覆盖

## 四、图标规范（2026-08-12 新增）

> 用户拍板：整个项目统一使用 Lucide 图标库。

1. **图标一律使用 `lucide-vue-next`**（已引入，^1.0.0）：`import { RefreshCw, X } from "lucide-vue-next"`，模板 `<RefreshCw :size="13" />`
2. **禁止用 emoji / Unicode 特殊符号充当按钮或功能图标**（🔄 ⧉ ☰ 📎 × [-] ⊞ 等均为历史遗留，已逐步替换）；emoji 仅允许出现在内容装饰（如 tip 前的语义标记）或对话正文中
3. **加载/忙碌态**：`<Loader2 class="animate-spin" :size="13" />`（lucide 组件 + tailwind 旋转类）
4. 尺寸惯例：图标按钮 13–14px（`<X :size="14" />`），带文字按钮内联 11px 并加 `mr-1 inline`
5. 引用组件名不存在时 typecheck（vue-tsc 模板检查）会报错——新增图标前确认名字存在于 `lucide-vue-next` 导出（如 Loader2 在新版本改名 LoaderCircle）

## 六、Git 提交规范

> 来源：cc-gui `CLAUDE.md`。格式以分形 AGENTS.md 为准。
### 6.1 格式

`<type>: <中文简短描述>`（type: feat / fix / refactor / chore 等），如 `feat: 新增用户登录`。

### 5.2 工作流（硬约束）

1. **积累，不微提交** — 不要在每次小改动后自动 commit。把改动留在工作树，等一个功能点完整实现后再提交。频繁的 `fix typo` / `adjust padding` 类提交会淹没真正的变更，让审查无法进行。
2. **一个功能点一个提交** — 每个 commit 是自包含、可审查的独立单元。相关改动归入同一个提交，不相关改动分开提交。原则：审查者能按顺序读 `git log --oneline` 就理解整个功能的演进。
3. **审查后提交** — 改动完成后先展示 diff 让用户审查，用户确认后再 commit。不要在用户不知情的情况下提交代码。
4. **推送前 squash** — 如果开发过程中产生了多个中间调整的提交，在推送到远程前用 `git rebase -i` squash 成有意义的几个提交。中间过程不需要进入共享历史。
5. **合并冲突处理** — 逐文件分析，不批量 `--ours` / `--theirs`；集合型文件对比两方条目数量手动合并增量；不确定时停止合并并询问（详见分形 AGENTS.md）。
