# v1.18.x — opencode.json 配置 Schema

> 适用版本：v1.18.x | 最后验证：待实测 | 验证方式：官方文档（opencode.ai/docs/config）+ 源码 + models.dev

## 关键字段（附录 A.3 结论，待逐项实测确认）

| 字段 | 用途 | 说明 |
|------|------|------|
| `provider` | Provider 配置 | DeepSeek 为内置 provider，仅需 `options.apiKey`（`{env:XXX}` 引用）+ `options.baseURL`；自定义 OpenAI 兼容需 `@ai-sdk/openai-compatible` |
| `model` | 默认模型 | `deepseek/deepseek-v4-flash`（v1.9 定案） |
| `mcp` | MCP 服务器 | local → `command` 数组；remote → `url` + `headers` |
| `skills` | 技能 | `paths` / `urls` |
| `plugin` | 插件 | npm 包或本地 ts/js 文件（`fractal`、`agents-priority`、superpowers、opencode-acp） |
| `permission` | 权限规则 | 三值 allow/ask/deny，按工具配置（见下）；对象语法按输入通配符细分；`external_directory` 工作区外路径；agent 定义内可覆盖（优先于全局） |
| `instructions` | 指令文件 | 预置规则 |
| `agent` | agent 定义 | 双星/工匠/参谋/军师（分形预置）；mode: primary/subagent/all；permission 可覆盖全局；prompt/model/temperature/steps/color 等 |
| `compaction` | 压缩 | `{"auto": false}`（使用 opencode-acp 时） |

## agent 详解（2026-08-05 官方文档查证）

- **OC 内置主 agent**：**Build（默认，全工具）** + **Plan（受限，edit/bash 默认 ask）**——Tab 键切换；分形预置将 `default_agent` 设为「双星」（oc-plus 做法），用户可切回 build/plan
- **内置子 agent**：General（通用）、Explore（只读探索）、Scout（外部文档/依赖研究）、隐藏系统 agent（compaction/title/summary）
- **配置项**：`description`（必填）、`mode`（primary/subagent/all，默认 all）、`permission`（ask/allow/deny + 对象语法，agent 级优先于全局）、`prompt`（`{file:...}` 引用）、`model`、`temperature`、`steps`（替代弃用的 maxSteps）、`disable`、`hidden`、`color`、`top_p`、`task`（permission.task 控制可调用的子 agent）
- **plan 模式官方实现**：primary agent + `permission: {edit: "ask"/"deny", bash: "ask"/"deny"}`——方案 3.5 的"用无写权限 agent 模拟 plan"由此得到官方验证（C-3 关闭）

## permission 详解（2026-08-05 官方文档查证）

- **可配置工具**：`read` / `edit`（覆盖 edit/write/patch）/ `glob` / `grep` / `bash`（匹配解析后的命令，如 `git status --porcelain`）/ `task`（匹配 subagent 类型）/ `skill` / `lsp` / `question` / `webfetch` / `websearch` / `external_directory` / `doom_loop`
- **对象语法**：`"bash": {"*": "ask", "git *": "allow", "rm *": "deny"}`；**最后匹配的规则生效**（catch-all `"*"` 放前面）
- **通配符**：`*` 零或多个字符、`?` 单字符；`~` / `$HOME` 展开（用于 external_directory）
- **默认值**：大部分 allow；`doom_loop` 与 `external_directory` 默认 ask；`read` 的 `*.env` 默认 deny
- **ask 弹窗**：once / always（仅当前会话）/ reject——always 的放行模式由工具提供（如 bash 白名单命令前缀）
- **auto**：`--auto` 启动参数（`opencode run --auto`），批准未显式 deny 的请求，`"deny"` 规则仍强制
- **agent 级覆盖**：`agent.<name>.permission` 或 agent md front matter `permission:` 块，agent 规则优先
- ⚠️ OC 无 CC 的 defaultMode 顶层模式概念——分形 GUI「模式」需翻译为规则集（方案 3.5 v1.12 修正）

## 配置来源与隔离（2026-08-06 实测）

- **加载顺序（后覆盖前，合并非替换）**：Remote（.well-known/opencode）→ 全局（`~/.config/opencode/`，Windows 受 `XDG_CONFIG_HOME` 控制）→ Custom（`OPENCODE_CONFIG` 指定文件）→ 项目（cwd 向上到 git 根找 opencode.json）→ `.opencode` 目录 → Inline（`OPENCODE_CONFIG_CONTENT` 内容）→ Managed（macOS /Library、Linux /etc/opencode、Windows `%ProgramData%\opencode`）
- ❌ **`OPENCODE_APPNAME` 不存在**（2026-08-06 查证：仓库代码/PR 均无）——早期方案该隔离变量为误记
- ❌ **`OPENCODE_CONFIG` 不能隔离**：合并叠加（全局仍全量加载，实测 debug config 含用户全部配置）
- ✅ **隔离正解 = `XDG_CONFIG_HOME` 注入**：serve 全局配置路径变为 `<XDG_CONFIG_HOME>\opencode\{config,opencode,opencode.jsonc}.json`（实测 serve 日志 loading 路径 + `opencode debug config` 只剩默认结构）；plugins/skills/agents 预置目录同步指向新位置；项目级配置（工作区 opencode.json / .opencode）不受影响
- **默认权限 = allow**（官方文档明确）：serve 下不配 permission 就不弹审批（S6 实测吻合）——分形「敏感操作 ask」必须显式写 permission 规则
- 其他 env：`OPENCODE_TUI_CONFIG`（TUI 配置）、`OPENCODE_CONFIG_CONTENT`（内联覆盖，最高运行时层）
