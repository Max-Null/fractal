## 一、V2 遇到的两类问题

### 问题 1：8800 端口冲突（serve 崩溃隐患，已降噪）

**现象**
- 分形 serve 启动日志（serve.log）反复出现：`Failed to start server. Is port 8800 in use?`
- 与 OpenCode 官方桌面端 / TUI 同时运行时，分形 serve 的 **v2 server 启动失败**（非致命：v1 API 正常，v2 路由也在 v1 端口——实测 /api/model 401 = 路由存在）

**根因（实测定案）**
- **8800 = serve 1.18.15 的 v2 server 默认端口**（与 `--port` 参数无关）
- **任何 opencode 客户端都占 8800**：官方桌面端（7 进程）、npm TUI（opencode.exe 实锤）——谁先起谁占
- 分形 `--port 0` 动态端口只能避开 v1 端口，v2 端口 8800 无法自选（OPENCODE_PORT env 注入无效——源码搜索 0 结果，1.x 不存在此变量）

**排查排除项（教训留档）**
- OPENCODE_PORT env 注入（buildServeEnv v2Port=port+1）：手动 spawn 不崩 vs 分形 app 崩——差异未彻底定位，已停止深挖（避免死循环）
- 二进制 strings 搜 8800：明文不存在（运行时计算）
- 项目/e2e 配置无 server.port=8800
- 社区无专门冲突 issue；#9099（导出 server URL env，open）、#21170（端口冲突静默退出，已修）、#38739（Bun EADDRINUSE 折叠）、#35158（V2 启动失败应显示可操作错误，open）

**处理（已提交 e3e3a91）**
- server-manager stderr tee：匹配 `/Failed to start server\. Is port \d+ in use/` → 控制台提示一次「检测到 8800 端口被占用（通常为 OpenCode 官方桌面端）——serve 的 v2 API 服务不可用；分形使用 v1 API，功能不受影响」（v2ConflictHinted 模块级跨重试一次）；serve.log 保留原文
- **架构结论**：`--port 0` + 降噪是 1.x 正解；真正根治 = OpenCode 2.0（Node 化内嵌，beta）——未来迁移候选（已写入知识库）

### 问题 2：V2 状态指示器「时序竞态」（已修复）

**背景**：降噪后用户无法感知 v2 不可用 → 新增指示器（D1-D7 设计）：
- V2Badge 顶栏胶囊（可用=主题色 accent / 不可用=coral 红）
- 载入完成冲突时顶部提示条一次（sessionStorage 记忆 `sb-v2-hint-shown`）
- V2Dialog 详情弹窗（V2 是什么 / 当前状态 / 建议动作——「关闭官方端/TUI 后点顶栏刷新按钮重新检测」——重新检测按钮已按用户反馈移除，复用刷新按钮）

**Bug（实测破案）**
- 用户实测「显示可用」但 serve.log 4 次冲突
- 排查链：链路代码全通（handleServeStderrChunk 调用 / toInfo 携带 v2Conflict / 广播 / 渲染层 ref）→ **加文件日志**：`16:30:25 getStatus false | running true` → `16:30:27 CONFLICT DETECTED`——**1.8s 时序竞态**：渲染层挂载即查早于冲突检测，冲突置位后无广播 → UI 永停 false

**修复（已提交，测试修复中）**
1. server-manager.ts：`v2ConflictListener` + `onV2ConflictChange(cb)`（工厂内挂 emitStatus）——置位即广播
2. AppShell.vue：`watch(v2Conflict, ..., { immediate: true })` 补提示条（sessionStorage 去重）
3. V2Badge.vue：去边框（对齐 icon-btn 兄弟按钮）
4. 清理 v2-debug.log 调试日志
- 用户验证：红色 ✅ / 提示条 ✅ / 边框 ✅
