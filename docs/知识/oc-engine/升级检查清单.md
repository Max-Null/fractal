# OC 升级检查清单

> 每次 OC 发布新版本时执行（sidecar 锁定版本，跟随 major/minor、滞后 1-2 个 patch——方案附录 E.2）。
> 目的：升级前先更新知识，再评估影响，最后才动 sidecar。

## 五步流程

- [ ] **1. 读 release notes**
  - [ ] 记录版本号、发布日期到版本矩阵
  - [ ] 按影响面分类：协议 / 插件 API / 配置 / 无影响
- [ ] **2. 更新知识库**
  - [ ] 版本矩阵回填一行（变更 + 影响模块 + 适配状态）
  - [ ] 对应知识文件更新（插件API/ACP协议/配置schema），版本锚点同步
  - [ ] 引用过时的结论标注修正（如仓库迁移类事件）
- [ ] **3. 跑契约测试**
  - [ ] `cargo test`（acp_client / oc_protocol fixture 回归）
  - [ ] oc-plus 插件冒烟（`~/.config/opencode/memories/debug.log` 无异常）
  - [ ] fixture 与新版报文结构 diff，漂移处记录到知识文件
- [ ] **4. 影响评估**
  - [ ] 决定：升级 / 观望（记录理由）
  - [ ] 观望时在版本矩阵标 `⏸️ 观望`，设定复查条件
- [ ] **5. 升级 sidecar + 回归**
  - [ ] 更新 `scripts/fetch-opencode-bin.ts` 锁定版本号
  - [ ] 重新下载二进制 + 三元组重命名
  - [ ] 无系统 OC 环境冒烟（独立运行验证）
  - [ ] GUI 全量冒烟（发送/流式/审批/恢复）

## 运行时探测

```bash
opencode --version        # 记录版本号（协议结论绑定该版本）
opencode models           # 模型 ID 清单（C-5 实测项）
```
