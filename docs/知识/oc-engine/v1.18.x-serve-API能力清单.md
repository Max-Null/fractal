## 四、能力边界结论（对上层设计的影响）

1. **排序/展示逻辑**：serve 无 sort → 前端排序（会话列表按 updated_at 倒序）——已定案
2. **v2 API 是未来**：官方 2.0 桌面端走 /api/* ——分形 oc-sdk 升级 v2 是中期方向（v2 有 compact/switchModel/switchAgent/wait 等产品级能力）
3. **可白拿的产品能力**（serve 原生，分形未用）：
   - 提问弹窗：question API（v1 + v2 都有）——P5 闭环
   - 撤销/重做：revert/unrevert（v1）或三段式（v2）
   - 上下文压缩：compact（v2）
   - 会话摘要：summarize（v1）
   - 权限规则管理：permission/saved（v2）
   - 全局搜索：find（v1）
   - 会话切换模型/agent：switchModel/switchAgent（v2）
4. **分形自行实现的替代品**（可考虑换 serve 原生）：git CLI（→ vcs API）、fs 直读（→ file API）——不必须换，但知晓 serve 有
5. **待实测项**：abort 500（C-15）、question 事件结构（P5）、compact 行为
