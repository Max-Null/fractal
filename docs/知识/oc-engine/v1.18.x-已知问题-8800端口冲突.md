# v1.18.x 认知更正：8800 端口占用真相与分形处理

> 锚点：serve 1.18.15（2026-08-10 认知更正，取代早期「官方桌面端占用 8800」的错误归因）

## 事实（实测定案）

- serve 1.18.15 启动时会额外启动一个 **v2 server**（默认端口 **8800**），与 `--port` 指定的 v1 API 端口相互独立
- **8800 的真正占用者是 scout-websearch 插件**（自研本地代理，固定监听 127.0.0.1:8800）——任何 opencode 实例（CLI / 官方桌面端 sidecar / 分形 serve）只要加载该插件就会抢 8800，谁先起谁占
- 官方桌面端本身不占 8800（其 server.log 无 v2 server 痕迹；此前「官方桌面端/TUI 占 8800」的结论是插件行为被误归因）
- 失败特征（stderr）：`Failed to start server. Is port 8800 in use?`（非致命——serve 主体继续运行）
- **v2 路由（/api/*）在 v1 端口同时存在**（实测 /api/model 在分形端口返回 401 = 路由存在）——分形 compact 走 v1 端口 v2 路由，不受 8800 影响

## v2 server 端口可控性（关键更正）

| 启动方式 | v2 server 端口 | OPENCODE_PORT env |
|---------|---------------|-------------------|
| `serve --port <固定值>` | 固定 8800 | **不生效**（源码无此读取路径） |
| `serve --port 0` | **跟随 OPENCODE_PORT**（注入随机端口即避开 8800） | ✅ 生效（实测） |

早期「OPENCODE_PORT 注入无效」的结论是在 `--port 固定值` 场景实测的，`--port 0` 场景下有效——分形当前即此用法。

## 分形处理（2026-08-10 定案）

1. **预置移除 scout-websearch.ts**：分形 ds-anthropic 直连官方端点（api.deepseek.com/anthropic），8800 代理对分形 serve 纯多余；oc-plus sync 已排除该文件（镜像语义清理存量）
2. **v2 server 避开 8800**：`--port 0` + `OPENCODE_PORT` 注入随机端口（server-manager buildServeEnv），与任何外部实例无争抢
3. **冲突检测体系删除**：v2Conflict 状态机 / V2Badge 指示器 / V2Dialog / 提示条全部移除（触发源消失后为死代码，e3e3a91 的降噪逻辑同步删除）

## 插件教训（全局适用）

- 插件内 `server.listen` 必须注册 **error 处理器**：EADDRINUSE 未处理会触发 `Unhandled 'error' event` → 杀死宿主 sidecar 进程（官方桌面端崩溃根因，issue #30597 模式）
- 端口类插件（固定端口代理）在多 opencode 实例并存时必然冲突，应：容错跳过 + 日志提示，而非直接抛错

## 未来根治（候选）

**OpenCode 2.0（beta 线）**：Node 化重写——引擎可进程内嵌入（端口自控），8800 冲突消失。1.x 的 `createOpencodeServer`（SDK）只是 spawn 二进制的封装（OpenChamber 即此用法，同样有 8800 行为）。2.0 稳定后分形迁移候选（D2 补充）。
