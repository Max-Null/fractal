# 分形会话机制（serve 事件订阅与消息流）

> 版本：v1.0 · 2026-08-12 · 锚点：OpenCode serve 1.18.15 / SDK 1.18.13
> 来源：8/11-8/12「GUI 卡思考中」根因排查实战调通（详见「历史教训」）

## 1. 架构总览

```
分形主进程 (electron/main)
  ├─ server-manager.ts  拉起 opencode serve（子进程，stderr 解析就绪信号）
  ├─ ipc.ts             startEngineEvents → establishSubscription（订阅 + 重连）
  ├─ events.ts          subscribeEvents（/global/event SSE 消费 → ServeEvent 分发）
  └─ session 相关       prompt_async 发消息 / event 驱动会话状态 / 标题更新
        │
        │ SSE（带 Basic 认证，端口 4096 v1 / v2 双版本共存）
        ▼
opencode serve（resources/bin/opencode.exe，--port 0 动态端口）
  └─ v1 /event         按「订阅时的当前实例目录」过滤（有坑，见 §3）
  └─ v2 /global/event  全局事件总线，不过滤（分形实际使用）
```

## 2. 事件订阅链路（分形实现）

- **端点**：`GET {baseURL}/global/event`（**v2 全局总线**）——serve 1.18.15 源码 `GlobalPaths.event = "/global/event"`；`/api/event` 不存在，命中 SPA fallback 返回 **200 HTML**（假成功、零事件——曾误导排查）
- **认证**：Basic（`OPENCODE_SERVER_USERNAME/PASSWORD`，serve 启动时生成，server-manager 注入子进程环境并保存）
- **SSE 解析**：手写 `\n\n` 分块 + `data:` 行 + `JSON.parse`（不依赖 SDK 的 createSseClient——其 fetch 无超时、404/断连指数退避无限重试，挂起永不恢复）
- **事件解包**：serve 推 `{ payload: { id, type, properties } }`——必须剥一层 payload
- **重连**：指数退避 3s 起 ×2 递增 30s 封顶；abort 信号驱动退出（应用关闭时干净断开）
- **就绪信号**：`waitEventConnected(timeoutMs)` = 等 serve stderr 出现 **`message=init`** 行（不是 event connected！见 §3）

## 3. 关键机制与坑（必须知晓）

### 3.1 v1 /event 按实例目录过滤（8/12 卡死根因）
- serve 源码：v1 handler 用 `filter9` 按 `event.location?.directory === instance.directory` 过滤——instance 是「**订阅时的当前实例**」
- 分形 serve 启动目录 = fractal（`--print-logs` 启动时当前实例）；用户活跃会话在**其他工作区**（如 doc-edit）时，serve 处理消息会实例化该目录 → 事件 location.directory ≠ fractal → **全部被过滤 → 主进程零事件 → GUI 卡「思考中」**（serve 实际正常处理完，页面无显示）
- 症状特征：serve.log 显示消息处理完成（loop/stream/exiting loop），但主进程 event-diag 零日志
- **结论：必须用 v2 /global/event（GlobalBus.on 直连，不过滤实例）**

### 3.2 `event connected` 回声不是就绪信号
- serve 日志里 `event connected` 是「有客户端订阅 /event 时的回声」（v1 handler 内），**不代表 serve 初始化完成**
- 等它 → 永远等不到（v1 无人订阅）→ 订阅被跳过 → 与 3.1 叠加造成「订阅从未建立」
- 正确就绪信号：stderr 的 **`message=init`** 行

### 3.3 认证与端口
- serve 固定端口 4096（v1）；`--port 0` 时实际端口从 listening 行解析（分形状态管理用实际端口）
- `/global/event` 无认证 → 401；带 Basic → SSE 流建立（挂起 = 连接成功）

## 4. 消息流与会话状态

- **发消息**：`prompt_async`（分形用字符串 model 兼容；v1.18.15 的 `/session/{id}/message` 端点要结构化 model 对象——分形不依赖）
- **事件驱动**：`message.updated`（part 增量）等事件 → 主进程 `toMessageData` 拼装 → 前端 store 更新
- **消息结构真相源**：assistant 消息 parts 的 `contentBlocks` 数组（时间线/思考/工具调用都从这里来）
- **标题**：`ensureTitle` 机制自动生成/更新会话标题
- **会话列表排序**：serve 默认 `time_created DESC`（v1 list 固定）；分形前端按 `updatedAt` 倒序显示（最近活跃优先）——注意 serve 侧无 order 参数

## 5. 相关数据隔离

- **XDG_DATA_HOME**：shared 模式下多 opencode 实例（官方桌面版/CLI）**共享 SQLite** → 锁竞争可致 serve 静默死亡（exit 4294967295 = 外部 TerminateProcess）——分形默认 **isolated**（`%APPDATA%\fractal\data`），与官方实例彻底隔离
- **会话存储**：isolated 库 `opencode.db`（session/message/part 表，part.data 是 JSON）
