# 分形 Debug 调试入口

> 排查「卡思考中」「会话状态不同步」等引擎无响应问题的三条通道。2026-08-10 新增。

## 通道一：应用内诊断面板（推荐，任何用户可用）

输入框左侧 **▸ 诊断信息** 按钮（**常显**，即使事件日志为空也可点开），面板三个标签页：

- **事件日志**：当前会话的前端事件记录（回合完成/错误/权限等）
- **引擎日志**：serve 进程完整输出（`--print-logs` 的 INFO 日志 + 错误），数据源为 `serve.log` 尾部 500 行，可手动刷新
- **控制台日志**：渲染进程 console 输出（仅调试模式启动时自动记录到 `renderer.log`），数据源为文件尾部 500 行

发送后卡「思考中」**30 秒无任何引擎事件**时，诊断面板会自动弹出并写入一条警告行——此时切到「引擎日志」页即可看到 serve 侧发生了什么（消息是否收到、模型调用是否开始、报错内容）。

## 通道二：调试模式启动（dev 或正式版）

**正式安装版**：命令行启动 `Fractal.exe --debug`（或设置环境变量 `FRACTAL_DEBUG=1` 后启动）。

**开发模式**：`npm run debug`（等价于 `OC_GUI_DEBUG=1` + `npm run dev`）。

调试模式下：

1. 应用加载完成后**自动打开 DevTools**（渲染进程 console/网络请求）
2. 渲染进程 console 输出**自动落盘** `renderer.log`（10MB 轮转）——应用内诊断面板「控制台日志」标签页可查看
3. serve stderr 已由主进程转发到终端（`handleServeStderrChunk`，500 字符截断）
4. 主进程自身诊断（窗口事件/引擎生命周期）输出到终端 + 落盘 `dialog.log`

## 通道三：serve 日志文件（最完整的原始输出）

| 文件 | 位置 | 说明 |
|------|------|------|
| serve.log | `%APPDATA%\fractal\logs\serve.log` | serve 完整输出（10MB 轮转，只保留 1 份旧档 serve.1.log） |
| renderer.log | `%APPDATA%\fractal\logs\renderer.log` | 渲染进程 console（**仅调试模式**启动时记录，10MB 轮转） |
| serve-crash-*.log | `%APPDATA%\fractal\logs\` | serve 异常退出（code!=0）时的 stderr 尾部转储（16KB） |
| dialog.log | `%APPDATA%\fractal\` | 主进程窗口/生命周期诊断 |

## 典型问题定位

- **发送后卡「思考中」且 serve.log 有消息接收/模型调用日志** → 引擎侧在处理，等事件流或看报错
- **serve.log 无任何输出** → serve 未收到消息或未启动成功（查 serve-crash-*.log）
- **会话列表绿点残留** → result 事件丢失（引擎重启窗口期）；刷新引擎或重载历史后会自动清除
